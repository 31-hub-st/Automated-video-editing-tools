## 0.4.8 员工版安装约定

- 必须复制或解压**整个发布目录**，不能只发送 EXE，也不能在 ZIP 内直接运行。推荐目录为 `D:\StoryForge`：路径只用英文字母、数字及常规 ASCII 符号，位于本地固定磁盘且当前用户可写。
- 不要安装到中文/Unicode 路径、`Program Files`、OneDrive/网盘同步目录、网络共享或 U 盘。程序会在不合格路径创建运行数据前直接停止并给出搬移提示。
- 首次启动由用户选择 `StoryForgeData` 数据目录；下文统一写作 `<StoryForgeData>`。设置、账号/连接状态、数据库、日志、WebView 数据、更新状态、渲染工作区、语言组件、模型与语音缓存和临时文件全部位于这里。程序目录与数据目录可以放在不同本地磁盘；员工选择的视频素材、音乐及最终输出目录也可独立设置。
- 核心程序更新包只能替换程序文件，**不得包含、覆盖或删除 `<StoryForgeData>`**。安装、排障、备份和卸载均以用户实际选择的数据目录为准。
- **0.4.2 升级到 0.4.3 是一次例外的受控迁移。**由于 0.4.2 旧更新器存在缺陷，严禁通过 0.4.2 的自动更新向员工机推送 0.4.3。管理员须先停止旧程序与 Worker，再把完整 0.4.3 包部署到 `D:\StoryForge`，由首次启动安全复制旧 C 盘长期数据。新目录已有文件不会被旧数据覆盖；旧设置、数据库、日志、命令/Manifest 和未知文件保留，缓存、临时文件、旧更新包和可重新生成的渲染媒体不会迁移。确认 0.4.3 真实任务成功前，不要人工删除旧 C 盘目录。
- 日志入口为 `<StoryForgeData>\logs`；单任务详细错误位于 `<StoryForgeData>\render-work\<批次>\<任务>\job-error.log` 或 `render-error.log`。完整迁移规则、更新流程和回滚步骤见 [Windows 部署说明](docs/DEPLOYMENT_WINDOWS.md) 与 [局域网软件更新](docs/AUTO_UPDATE.md)。

局域网网页端与桌面端使用同一套账号、页面和制作能力。浏览器中的资料操作由 Hub 处理；试听配音、选择素材、FFmpeg 渲染和输出则交给当前员工电脑的“本机制作服务”。员工首次在 EXE 中用账号密码登录后，该服务会自动登记并随 Windows 登录运行，无需一直打开 StoryForge 完整窗口。最短使用流程见 [网页端使用说明](docs/WEB_ACCESS.md)。

StoryForge Studio 是一款 Windows 本地优先的小说推文视频生产工具：导入 TXT/DOCX 或粘贴正文，软件会识别正文语种，并由所选文本服务判断悬疑、浪漫、悲伤或爽文题材；再维护推广平台、口令和发布账号，在一页制作台为本批选择女声、字幕、素材与视频模板。操作者先在浏览器中即时查看开头、字幕和结尾样式，再直接创建 9:16 MP4 完整任务；即时预览只是界面效果预览，不会生成待审批的视频文件。当前版本不会登录或上传 TikTok，也不会替你购买任何云服务。

面向二次开发、系统集成和功能嫁接，请先阅读 [0.4.0 多电脑生产验收门槛](docs/V0.4.0_MULTI_PC_ACCEPTANCE.md) 和 [整体项目与功能嫁接说明书](docs/STORYFORGE_INTEGRATION_REPORT.md)。完整需求边界见 [V2 产品需求基线](docs/PRODUCT_REQUIREMENTS_V2.md)，其他电脑和多电脑协同的操作见 [Windows 部署说明](docs/DEPLOYMENT_WINDOWS.md)。

## 当前版本已覆盖的流程

- 建立长期资料库，集中维护小说正文与版本、故事简介、封面、章节/分集、推广平台、历史口令和人工发布账号；资料库卡片优先显示已上传的小说封面，只有没有封面时才显示系统占位图。
- 导入时根据正文自动识别英语、简/繁中文、西班牙语、葡萄牙语、印尼语、法语、德语、日语和韩语；资料库只显示实际存在的语种及数量，并支持按语种筛选、人工纠正和重新检测。证据不足或多语混排会标为“未识别/混合语种”，不会硬猜成英语。
- TXT 支持 UTF-8、UTF-16、GB18030、Shift-JIS 和常见西文编码，并拒绝明显的二进制或乱码文件。
- 兼容 `口令_小说标题.txt` 文件名，口令支持英文字母和数字，例如 `B73165_The Last Promise.txt`；新流程也可在小说平台绑定中手动选择口令。
- 修复常见英文乱码，跳过 `Chapter 1` 这类章节标题，在章节位置加入短暂停顿。
- 保留完整剧情，只删除重复表达，通常目标保留率为 85%–90%；原文无明显重复时不会为了凑比例强行删剧情。可选“保留直接表达”或“增强吸引力”。
- 由文本服务生成故事专属开头钩子、润色正文、题材分类和结尾引导。分类会读取简介以及正文开头、中段和结尾的抽样；云端或本地大模型不可用时回退到本地规则，不会阻止选书。制作台显示分类来源并允许人工改选。
- 制作台为每批提供 3 个美式英语女声候选；试听后选定本批女声，本批所有分集保持同一声音，下一批仍可重新选择。
- 删除素材原声；视频素材只从员工本批手动选择的文件夹递归读取，不再依据小说题材选择或要求题材子目录。素材不足时自动拼接，必要时通过起始位置、镜像、裁切和复用形成不同画面组合；竖屏采用模糊背景保留完整画面。
- 小说题材仍用于内容分析、女声和音乐建议，但不会控制视频素材目录。背景音乐不足时自动循环，并始终保持在旁白之下；员工可手动指定音乐或关闭 BGM。
- 提供“经典模板”和“平台简介卡”两种视频模板。“平台简介卡”在前 5.5 秒显示钩子标题、平台口令和小说简介/正文摘录，随后保留顶部搜索卡与语义短语字幕。封面结尾现在是批次和生产预设中的可选项：开启时让小说封面以所选动效铺满全屏，关闭时保持正文画面并继续播放 CTA 旁白与字幕；两种模式都不再叠加白色平台卡。顶部搜索口令卡全程保留；不复制参考视频的素材或音乐。
- 三种方式严格分开交付：常规视频生成只输出 H.264、1080×1920 MP4；仅生成配音只输出 48 kHz、192 kbps MP3；已有配音更换素材只输出新 MP4。常规视频不会再额外复制一份旁白 MP3。视频默认 60 FPS，兼容模式可改为 30 FPS。
- 一个批次只对应一部小说和一个推广平台；可选择一个或多个分集/子段，并填写本批生成总视频数。所选内容按正文顺序合并成一条连续视频的内容单元，总视频数表示该合并内容要生成的去重版本数量，不再按分集均分。选择从第 1 集开始时不生成上集回顾；从后续集开始时只在整组开头生成一次回顾。合计预计超过 10 分钟只显示提醒，不拆成多条视频。生成数量不设产品上限，大批量采用磁盘计划、分块落库和小窗口队列，实际规模只受磁盘、上游额度和处理时间约束。
- 一页制作台同时配置本批女声、WPM、音乐音量、字幕、封面结尾开关与动效、视频素材目录、音乐目录、输出目录和制作方式，不会把这些生产参数锁死在小说资料中。兼容接口值仍为 `video_and_mp3 / audio_only / reuse_audio`，但 `video_and_mp3` 在 `0.4.8` 的当前交付合同中只发布 MP4；要保留可复用旁白时应单独选择 `audio_only`。
- 制作台右侧即时预览会随开头、字幕、口令卡、小说封面和结尾动效配置同步变化。它是浏览器渲染的界面预览，不生成 MP4、WAV 或其他审核文件，也不存在确认放行步骤。提交后系统直接创建 `job_kind=full`、`status=queued`（接口值为小写 `full` / `queued`）的完整任务，并写入 `preview_required=false`；失败项跳过，其他任务继续。
- 批次提交成功后，已经排队的配置立即冻结，制作台同时切换成一个没有草稿 ID 的新批次。新批次保留上一批的女声、WPM、字幕/画面样式、渲染选项以及当前电脑的视频、音乐和输出目录，但会清空口令、发布账号和分集，要求重新选择后再提交。操作者无需等待上一批完成，可以连续建立任意多个批次；本机严格按提交顺序 FIFO 制作，前一批即使包含流式尾部任务也不会被后一批插队，某条视频或整批中的部分任务失败也不会阻塞后续任务和批次。
- 制作电脑采用单重任务资源治理：后台状态明确区分空闲、制作、暂停、排空、冷却与故障，内存、磁盘和 GPU 不满足安全阈值时不会盲目启动下一条重任务；连续可重试故障会进入有上限的冷却期，避免后台反复拉起导致卡顿。
- 每条任务记录“文本、配音、字幕、素材预检、渲染、质检、发布”七阶段及耗时，制作台直接显示失败阶段和恢复建议；同一条任务不会因为旧 Worker 的迟到回调覆盖新进程结果。
- “设置 → 服务与本机运行环境”可先扫描本机空间、预览可安全清理内容，再显式确认清理；小说源文件、最终 MP4/MP3 和当前更新包始终受保护。管理员可一键生成经过脱敏的诊断 ZIP，用于定位员工电脑环境问题。
- 核心更新包必须携带与实际 ZIP 内容逐文件匹配的冻结发布证明；同版本组件也会重新核验并修复损坏文件，激活失败时自动恢复旧状态和上一版运行时。
- 正文存在显式 `Chapter`、`Episode`、`Part` 等分集标题时，每个分集保持为独立可选单位，短集不会在资料库导入阶段跨章静默合并；原始长分集预计超过 10 分钟时可在完整句子和悬念处规划为可选子段，没有显式分集标题时才按全文长度规划可选段。这只是资料库的可选单位规划；制作台提交时仍把本批勾选项合成一条连续视频。E001/E002 只进入后台、目录和文件名。
- 失败任务自动跳过并保留具体原因，其他任务继续；成片完成后执行快速可播放性与参数检查。
- 可指定一台电脑运行 StoryForge Hub，让任意数量的制作电脑共享小说、平台口令、账号、大模型、生产预设、草稿与生产记录；各制作电脑继续使用自己的配音运行时、视频、音乐、字幕处理、FFmpeg/GPU、临时文件和输出目录，不把渲染压力集中到主机。最终 MP4、仅配音模式的 MP3、内部 WAV、ASS 和字幕对齐文件始终只保存在生成它们的员工电脑；Hub 只登记业务记录、摘要校验和本机受控引用，永不上传生产媒体。Hub 固定资料备份保留 72 小时、最多 3 份；内容相同的快照按内容摘要去重，不重复占用空间。
- 软件账号只分管理员和员工两种角色：管理员负责资料、团队与多电脑设置，员工负责日常制作；个别例外仍可在默认折叠的高级权限中调整。
- 制作电脑首次接入只需双击 `StoryForge Studio.exe`，输入成员账号和密码。软件自动发现 Hub、读取 Windows 电脑名称、登记设备并启用本机制作服务；员工不填写其他连接信息。
- 在视频素材目录记录使用次数，优先选择使用次数更少的素材。
- 任务胶片带按 `batch_id` 聚合为可折叠的“批次卷宗”，默认先看批次总体进度和成功/失败数量；展开后查看单条视频、错误和操作，并可跳转到对应生产记录。当前队列和持久归档仍分开保存；归档历史分页加载，可恢复但不会删除员工电脑上的成片或日志。

语种识别与配音能力是两件事：默认仍为美式英语，当前完整包继续内置可工作的日语组件及约定女声；可选 Edge TTS 客户端进一步覆盖德语、印度尼西亚语、韩语等语种。Edge 候选来自当前电脑实时读取的上游女声目录，组件、网络或对应女声不可用时返回空结果，不用静态假 ID 凑满三个。后续新增或升级日语、法语、德语等语言资源时使用独立的安全组件包，安装到 `<StoryForgeData>\components`；组件包校验兼容版本和 SHA-256，安全解压并原子切换，可回退上一版，不要求每次重打完整 EXE。

## 0.4.8 网页与桌面同功能的本机制作模式

Hub 主电脑启动后，同一套 UI 可运行在桌面 WebView、Hub 团队网页和制作电脑的本地网页中。当前 Hub 地址为 `http://10.0.0.225:8765/`，仅供管理员维修和网络诊断；员工不需要手工填写。员工在完整发布目录中双击 EXE，输入账号密码后，软件会自动完成 Hub 发现、设备登记和本机制作服务启用。此后可以关闭 StoryForge 完整窗口；Hub 页面会通过短时设备票据连接该服务，在当前员工电脑完成候选配音、本机素材选择、字幕、队列、FFmpeg 和成片输出。

网页和桌面“同功能”指两者都能完成同一套业务流程，而不是让普通浏览器直接读取磁盘或运行 EXE。浏览器自身受安全限制，必须通过当前电脑的本机制作服务使用该电脑的 Kokoro/Edge/云 TTS、视频、音乐、FFmpeg/GPU 和输出目录。Hub 只提供小说库、平台口令、账号、大模型、团队预设、任务元数据和记录；管理员在其他电脑打开 Hub 时看不到员工电脑上的成片文件。即时预览由浏览器直接呈现，不会先渲染视频文件；浏览器关闭不会取消已经提交给本机制作服务的完整任务。

当前提交流程固定为“选择内容 → 配置声音与画面 → 查看即时预览 → 直接生成完整视频”。点击生成后，每个任务直接以 `full + QUEUED` 进入队列（序列化字段为 `job_kind="full"`、`status="queued"`、`preview_required=false`），不会创建 `preview` 任务，不会停在等待确认状态，也不需要审批后再放行。提交成功后制作台立即成为下一批的新草稿；上一批继续在后台制作，下一批重新选择口令、发布账号和分集即可再次提交。所有已提交批次都有独立 `batch_id`、持久化总数和总体进度，界面只返回部分任务窗口时也不会把窗口条数误当成整批总数。

Hub 主机与制作电脑使用两个不同的后台服务：Hub 主机由管理员启动团队网页；员工电脑的本机配音、目录与渲染服务在 EXE 首次账号密码登录时自动安装并启动。二者都不要求完整桌面窗口常开。`admin-tools` 中的启用/停用脚本只供管理员故障修复或撤销服务，不属于员工正常使用流程。

- 网页账号只有管理员和员工两类，并继续叠加账号级权限覆盖。员工默认只能看到和操作自己的草稿、任务与记录；服务端会重新注入当前 actor，不能由前端伪造所有者。员工左侧保留“设置”，但只显示个人制作默认值、本机 FFmpeg/TTS/编码器维护和当前电脑的软件更新；小说、平台口令、成员、Hub、密钥与团队默认仍只对管理员开放。
- 生产方案只保留“团队默认 + 个人方案”：团队默认由管理员在设置中维护，只影响之后新建的批次；员工可以保存、修改和删除自己的个人方案，管理员可以查看和删除全部成员方案。旧版内置方案、团队共享方案和无所有者方案不再显示，也不会被自动套用。Hub、桌面桥和草稿保存都会按当前账号重新校验所有者，不能靠伪造方案 ID 越权套用或覆盖。
- 成员密码固定为 8 个可见 ASCII 字符，可自由组合字母、数字和标点；新员工默认密码为 `xs123456`。首次登录后建议自行修改，但当前版本不强制，也不把改密作为接入或生产验收门槛。制作电脑只用“账号 + 密码”登录，Hub 与设备身份由软件自动处理。Hub 网页使用 HttpOnly、SameSite Cookie，所有写操作还需要当前会话的 CSRF 安全校验；制作电脑本地网页只监听 loopback，并在每次请求重新校验 Hub 账号、设备和权限状态。
- TXT/DOCX、封面、平台 Logo 和管理员更新 ZIP 必须通过受控上传接口进入 Hub；Hub 网页不能提交任意主机绝对路径。制作电脑的本地网页只允许使用本机默认工作目录或本机已登记的安全根目录，跨电脑草稿中的旧绝对路径不会直接继承。
- 管理员可在 Hub 网页发布核心程序更新包；制作电脑默认自动检查、下载、校验，并在渲染空闲的安全重启点安装。语言组件包走独立校验、原子安装和回退流程，不与核心 EXE 更新混装。Hub 页面随主机升级刷新；制作电脑本地网页来自该电脑自己的程序版本。
- 默认监听为明文 HTTP，仅适合可信专用局域网。不要把 8765 直接映射公网；跨地点应先建立可信 VPN。正式公网接入还需 HTTPS 反向代理、速率限制、集中审计与独立发布签名。

接口与安全边界详见 [网页端使用说明](docs/WEB_ACCESS.md) 和 [整体项目与功能嫁接说明书](docs/STORYFORGE_INTEGRATION_REPORT.md)。

### 历史 preview 兼容边界

`job_kind="preview"`、`preview_file`、`preview_uri`、`preview_approved`，以及 `previewing`、`awaiting_approval`、`waiting_preview`、`approved` 等状态仍保留，只用于读取和迁移旧版本数据。`0.4.8` 的通用失败重试明确拒绝历史 preview；`approve_preview`、`regenerate_preview` 和历史 `sample` / `preview_narration` / `preview_alignment` 代码只作反序列化与旧数据兼容，当前 UI 和 client-local 网页均无入口。二次开发不得把它们作为当前生产流程的一部分。

## 推荐的素材目录

平台不需要单独占一个文件夹。平台名称、屏幕口令和结尾旁白保存在“资料库 → 平台与口令”中；发布账号也在资料库统一登记。视频、音乐和输出目录在制作台按批次选择，可以使用各台电脑自己的磁盘布局。

推荐示例：

```text
D:\StoryForgeMedia\
├─ novels\2026-07-20\
│  ├─ B73165_The Last Promise.txt
│  └─ 845217_A Marriage of Revenge.txt
├─ videos\
│  ├─ long\
│  ├─ recent\
│  └─ any-subfolder\
├─ music\
│  ├─ 悬疑\
│  ├─ 浪漫\
│  ├─ 悲伤\
│  └─ 爽文\
└─ output\
```

注意事项：

- 使用兼容文件名自动识别口令时，TXT 文件名开头应由英文字母和/或数字组成，随后紧跟一个下划线；标题可以包含空格和更多下划线。通过界面导入时也支持 DOCX 或直接粘贴正文，平台和口令可在资料库中手动绑定。
- TXT 建议使用 UTF-8；软件也会尝试修正常见的 Windows-1252/UTF-8 乱码。
- 视频支持 MP4、MOV、MKV、WebM；音频支持 MP3、WAV、M4A、AAC、FLAC、OGG、Opus、WMA。
- 视频素材可按员工自己的习惯建立任意子目录。系统只递归读取本批明确选择的文件夹，不读取小说题材来决定视频目录，也不会因为没有 `悬疑/浪漫/悲伤/爽文` 子目录而报错。
- 员工选择的视频素材文件夹中完全没有可解码视频时才明确失败并跳过。音乐仍可自动建议、手动指定或关闭，并按成功使用次数、时长适配度和路径稳定性选择。
- 不要删除视频目录中的 `.storyforge-media-usage.json`，它用于减少素材重复。
- 每条小说建议使用不同口令；当前版本不会阻止重复口令。

## 第一次运行

系统要求：Windows 10/11 64 位、Python 3.11 或更新版本，以及 Microsoft Edge WebView2 Runtime。多数 Windows 10/11 电脑已自带 WebView2。如果要安装或打包进程内 Kokoro，请使用 Python 3.11–3.12；当前 Kokoro 依赖不支持 Python 3.13。

推荐使用虚拟环境：

```powershell
Set-Location -LiteralPath 'C:\codex tools\文转音频匹配字幕'
py -3 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements.txt'
& '.\.venv\Scripts\python.exe' '.\run.py'
```

也可以直接运行辅助脚本。脚本优先使用项目 `.venv`，否则使用当前环境中的 Python，安装基础依赖后启动软件：

```powershell
& '.\scripts\run_dev.ps1'
```

调试界面：

```powershell
& '.\scripts\run_dev.ps1' -Debug
```

如果已经安装依赖，可加 `-SkipInstall`。需要指定解释器时使用 `-PythonExe 'D:\Python312\python.exe'`。

## 首次配置与批量渲染

1. 在“资料库 → 平台与口令”建立推广平台，填写平台名、常驻口令卡和结尾旁白模板。
2. 在“资料库 → 小说资料”粘贴或导入 TXT/DOCX；补充简介和封面，检查按正文标题识别出的分集。资料库优先显示上传封面，无封面时才显示占位图。显式分集保持独立；原始长分集超过 10 分钟时可规划可选子段，无显式标题时才按全文规划可选段。该规划不会决定本批视频数量，制作台仍由员工勾选后合成为一条连续视频。为小说绑定平台并录入口令，每个“小说 × 平台”历史累计最多 5 个。
3. 如需归类，在“资料库 → 发布账号”登记人工发布账号；也可以保持“待分配”。资料库只保存这些长期固定资料。
4. 进入“制作台”，点击小说区域打开带封面和搜索的可视小说库；可以按平台、语种筛选，也可以在搜索框输入题材名称。选择一部小说后，设置本批平台和口令、发布账号、一个或多个分集及生成总视频数；所选分集按顺序合并为一个连续内容，总数表示该内容的去重版本数，不设业务数量上限。
5. 软件自动给出题材建议，用于内容、女声和音乐参考；视频素材不按题材自动匹配，由员工直接选择本批素材文件夹。试听真实女声并选择本批统一女声后，再设置视频模板、WPM、背景音乐音量、字幕预设与切分方式、封面动效、渲染模式，以及本机视频、音乐和输出目录。开头、正文字幕、顶部口令卡和封面结尾会同步反映在右侧即时预览中。
6. 在即时预览中检查版式和效果；重点确认顶部口令卡全程可见、结尾小说封面铺满全屏、CTA 旁白使用普通字幕同步显示。确认配置后点击“直接生成完整视频”，系统立即把本批完整任务加入队列；不会生成或审批中间视频文件。
7. 提交成功后不用等待：制作台会保留女声、样式、节奏和本机目录，清空口令、发布账号与分集并进入下一批。重新选择这三项即可继续提交；多个批次按提交先后严格排队。任一视频失败会记录原因并跳过，不会让后续视频或下一批停住。

员工选择的输出目录只展示便于发布的批次文件夹：`待发布/<平台>_<口令>_<小说>_B<批次8位>/`。常规视频生成只平铺最终 MP4；`audio_only` 固定只生成一份最终 MP3；`reuse_audio` 使用带可靠字幕索引的配音 MP3 更换视频素材并只生成新 MP4。文件名包含批内序号、平台、口令、E001/E002、变体号和批次短 ID。`manifest.json`、`quality-check.log`、ASS、内部 WAV、原稿、旁白稿、渲染命令、恢复日志和缓存统一放在 `<StoryForgeData>\render-work\<批次>\<任务>\`，不混入员工可见的批次发布文件夹。旧接口值 `video_and_mp3` 为兼容保留，但当前只发布 MP4；旧记录继续兼容读取。

## 女声服务

### 本地 Kokoro（推荐的永久兜底）

源码模式下安装可选依赖：

```powershell
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements-ai.txt'
```

如果没有使用虚拟环境，也可执行：

```powershell
& '.\scripts\setup_local_ai.ps1'
```

“Kokoro 本地地址”留空时，只有已安装 `requirements-ai.txt` 或使用 `-WithLocalAI` 构建的**完整版**才能调用进程内 Kokoro。源码模式若未准备模型，首次配音会下载模型并保存到 Hugging Face 缓存。离线完整版必须在 EXE 同级保留完整的 `local-ai\kokoro` 模型目录；找到这组离线文件后不会再依赖首次联网下载。

**轻量版与完整版不是同一套本地配音能力。**轻量版包含网页/桌面界面和 FFmpeg，但不包含 Kokoro/PyTorch 运行时；因此页面显示“Kokoro 还未配置”是正确状态，不代表 FFmpeg 或网页坏了。轻量版可选择 Edge TTS、Deepgram，或在“Kokoro 本地地址”中填写可访问的 OpenAI-compatible Kokoro HTTP 服务。完整版才可在地址留空时直接使用内置 Kokoro。网页显示的 Kokoro 状态来自当前员工电脑的本机制作服务，不来自 Hub 主机；Hub 装有 Kokoro 也不会自动替员工电脑配音。

题材声音使用语义档案，切换服务时自动映射：戏剧张力、温暖亲密、冷静低沉、清晰强势。同一批视频只使用一个选定女声，但下一批可重新试听和选择，并默认沿用上次成功音色。默认目标语速为推荐档 240 WPM；制作台提供舒适 220、推荐 240、快速 260、极快 280，以及 200–280 WPM 自定义值。切换语速会生成并自动播放 8–12 秒真实试听，缓存相同小说、声音和语速的结果。视频素材速度由员工固定选择，支持 1.0/1.1/1.25/1.4/1.5× 预设及 0.8–3.0× 自定义；多素材优先硬切，也可选择 0.2 秒柔和过渡，不进行智能变速或渲染后的相似度扫描。背景音乐默认 28%，可自动匹配、手动指定或完全关闭；启用时旁白出现会自动压低音乐而不会盖过人声。

本地和云端配音都会使用逐句 WAV 缓存；相同文本、服务、模型、女声和语速再次生成时会直接复用，任务中断后也能保留已经完成的句子。缓存位于用户选择的 `<StoryForgeData>\cache\tts`。

### Edge TTS（无需 API Key，需联网）

标准源码依赖已包含 `edge-tts>=7.2,<8`。若当前电脑是旧环境，可在该电脑执行：

```powershell
python -m pip install "edge-tts>=7.2,<8"
```

选择 Edge TTS 后，候选生成会实时读取上游女声并按小说语种筛选，最多返回 3 个不同女声；当前已覆盖 `en / ja / es / fr / de / id / ko / it / pt-br / hi`，实际数量以上游当时返回为准。该服务不需要 API Key，但不是离线引擎，试听和正式制作均需要当前制作电脑能够联网。下载的压缩语音会在本机通过 FFmpeg 转为 24 kHz 单声道 PCM WAV，再进入统一缓存、字幕和渲染流程。

### Deepgram Aura

截至 2026-07-20，Deepgram 官方定价页说明新账号提供一次性 200 美元免费额度，注册无需信用卡；这不是每月刷新的免费层，额度用完后转为按量付费。详见 [Deepgram 官方定价](https://deepgram.com/pricing)。

选择 Deepgram，填写 API Key；API 地址留空会使用供应商默认语音地址。软件按本地字符账本检查“硬性月字符上限”，达到上限后停止调用。`0` 表示不设置本地上限，不代表云端无限免费。服务商政策可能变化，请在注册时再确认账号页；本软件自身不会绑定银行卡、升级套餐或自动付费。

如果 Deepgram 失败且启用本地回退，系统会尝试 Kokoro。要确保回退可用，必须已安装进程内 Kokoro，或在设置中填写可用的 Kokoro 本地服务地址。

## 打包 Windows EXE

构建脚本使用独立的 `.build-venv`，不会覆盖当前 Python 环境。团队员工版必须在构建时写入 Hub 地址；该文件只含公开地址，不含账号、密码或内部设备凭据：

```powershell
& '.\scripts\build_exe.ps1' `
  -OutputDirectory 'D:\StoryForgeBuildTemp\dist' `
  -WorkDirectory 'D:\StoryForgeBuildTemp\work' `
  -HubEndpoint 'http://10.0.0.225:8765'
```

生产构建应始终像上面一样显式传入两个纯英文/ASCII 目录。若仅作本机临时构建且省略这两个参数，脚本在源码路径含中文时会自动改用源码所在盘根目录下的 `StoryForgeBuildTemp\dist` 与 `StoryForgeBuildTemp\work`，避免 PyInstaller 在中文工作路径中失败。

默认生成 onedir 发布目录：

```text
dist\StoryForge Studio\
├─ StoryForge Studio.exe
└─ storyforge-connection.json
```

`0.4.8` 自动化门禁覆盖冻结态启动、内置 FFmpeg/TTS、三种制作方式的契约与迁移；正式包另外完成冻结 EXE 的 311 秒和 600 秒真实长渲染。员工电脑的驱动、目录和真实素材仍需在更新下载后各完成一次硬件冒烟，不能用构建机结果代替。核心程序安装与 Hub 更新使用同一个已验收 ZIP，ZIP 根目录不包含 `StoryForgeData`；语言组件包独立构建、校验和发布。当前交付证据见 [0.4.8 稳定版交付报告](docs/V0.4.8_STABLE_RELEASE.md)，历史信息见 [0.4.7 稳定版交付报告](docs/V0.4.7_STABLE_RELEASE.md)。

普通本地开发或候选包继续使用上面的快速构建命令，不会运行 10 分钟稳定验收。正式 Release 构建必须同时显式传入 `-ReleaseBuild` 和 `-RequireStableAcceptance`；缺少后者会在安装依赖和打包前直接失败：

```powershell
& '.\scripts\build_exe.ps1' `
  -ReleaseBuild `
  -RequireStableAcceptance `
  -WithLocalAI `
  -OutputDirectory 'D:\StoryForgeBuildTemp\release-dist' `
  -WorkDirectory 'D:\StoryForgeBuildTemp\release-work' `
  -HubEndpoint 'http://10.0.0.225:8765'
```

Release 路径会绑定并检查冻结 EXE 的稳定验收报告、发布目录证明和独立包体冒烟报告；后者位于 `<WorkDirectory>\release-gate\package-smoke.json`。GitHub Actions 的快速 PR、夜间全量回归和正式发布门禁，以及本地复核命令见 [发布与回归门禁](docs/RELEASE_GATES.md)。这些门禁只上传测试摘要，不自动发布软件，也不需要私密 Token。

指定输出目录：

```powershell
& '.\scripts\build_exe.ps1' `
  -OutputDirectory 'D:\StoryForgeBuildTemp\dist' `
  -WorkDirectory 'D:\StoryForgeBuildTemp\work' `
  -HubEndpoint 'http://10.0.0.225:8765'
```

轻量 EXE 包含桌面/网页界面、本机制作服务和 FFmpeg，但不捆绑体积较大的本地 Kokoro/PyTorch 运行时。轻量版可使用 Edge TTS、Deepgram，或连接独立的本地 Kokoro HTTP 服务。完整窗口关闭后，已启用的本机制作服务仍可继续为网页提供上述能力。

需要把进程内 Kokoro 一并打进 EXE 时，在配置较好的构建电脑上运行：

```powershell
& '.\scripts\build_exe.ps1' `
  -WithLocalAI `
  -OutputDirectory 'D:\StoryForgeBuildTemp\dist' `
  -WorkDirectory 'D:\StoryForgeBuildTemp\work' `
  -HubEndpoint 'http://10.0.0.225:8765'
```

`-WithLocalAI` 会把 Kokoro/PyTorch 运行时收进 EXE，并校验、复制源码根目录 `local-ai\kokoro` 到发布目录。若源码根尚未准备离线资产，先导出完整模型与多语种女声：

```powershell
& '.\scripts\export_kokoro_offline_assets.ps1' `
  -Destination '.\local-ai\kokoro' `
  -PythonExe '.\.build-venv\Scripts\python.exe'
```

发布目录的必要结构如下。分发到其他电脑时必须复制整个目录，不能只复制 EXE，也不要在压缩包内直接运行：

```text
StoryForgeBuild\
├─ StoryForge Studio.exe
├─ storyforge-connection.json     # 仅包含团队 Hub 地址，不含密码
├─ QUICK_START.md
├─ admin-tools\                   # 管理员维修工具，员工正常流程不进入
│  ├─ enable_storyforge_worker.cmd
│  ├─ disable_storyforge_worker.cmd
│  └─ diagnose_storyforge.cmd
└─ local-ai\kokoro\
   ├─ config.json
   ├─ kokoro-v1_0.pth
   └─ voices\
      ├─ af_*.pt / bf_*.pt
      ├─ ef_dora.pt / ff_siwis.pt
      ├─ hf_*.pt / if_sara.pt
      ├─ jf_*.pt / pf_dora.pt
      └─ zf_*.pt
```

本地 AI 版会明显增大分发体积，构建和首次模型预热可能需要较长时间。建议在一台没有 Python、断网或受限网络的 Windows 电脑上测试候选配音、浏览器即时预览联动和一条完整成片。即时预览不需要随安装包分发缓存视频，也不应作为部署健康检查的文件产物。

发布版可先执行 `& '.\StoryForge Studio.exe' --kokoro-self-test '.\kokoro-check'`，确认生成自检 WAV/JSON 后再打开界面。该自检会绕过业务语音缓存并强制执行一次新合成，旧 WAV 不会造成“假通过”。

发布前至少运行当前生产流程与 UI 契约测试：

```powershell
python -m unittest tests.test_production_workflow tests.test_ui_contract
```

人工验收时应切换开头、字幕和封面动效预设，确认右侧即时预览同步变化；随后创建一个最小批次，确认新任务直接为 `full + QUEUED`，没有新增 `preview` 任务或等待审批状态。最终 MP4 还应检查顶部口令卡全程可见，以及结尾小说封面全屏动效、CTA 配音与普通字幕同步。

如果 PowerShell 阻止本地脚本，仅对当前进程放行即可：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

| --- | --- |
| 仅云端文本/语音，偶尔渲染 | 4 核 8 线程、16 GB 内存、SSD 至少 20 GB 可用空间；可用 CPU 编码，但长视频较慢。 |
| 日常批量生产 | 8 核 16 线程或更高、32 GB 内存、NVMe SSD 至少 100 GB 可用空间。 |
| 本地 Ollama + 本地 Kokoro + 批量渲染 | 32 GB 以上内存、NVIDIA 8 GB 以上显存、较新的驱动；模型和中间 WAV 会占用较多空间。 |

软件会在运行时测试 NVENC、Intel QSV、AMD AMF；可用时优先硬件 H.264，否则自动使用 `libx264`。60 FPS 的编码量和文件体积通常高于 30 FPS，配置较低或追求更快出片时可切换 30 FPS。长小说的旁白 WAV、字幕和视频中间文件可能数倍于最终 MP4，输出盘应预留充足空间。

## 当前第一阶段边界

- 默认生产语言为美式英语；非英语正文可入库、分类并按已安装的 Kokoro、Edge TTS 或 Deepgram 语种能力选择女声。Edge TTS 在每台制作电脑本地运行客户端并在线取声，不把 TTS 压力转移到 Hub。
- 资料库导入时，有明确分集标题就保持为独立可选集；原始长集可规划子段，无标题正文才自动规划可选段。制作台提交时，员工勾选的全部分集/子段始终按顺序合成一条连续视频，超过 10 分钟只提醒，不自动拆分或极端加速。
- 暂不生成 TikTok 标题、发布描述和标签。
- 不包含 TikTok 登录、自动上传或定时发布；发布账号只用于人工归类与回填。
- 不包含平台合规检查，也不保证任何内容一定通过审核；发布者仍需自行核对版权、成人内容和平台政策。
- 软件不替用户注册云端账号，也不查询供应商实时剩余额度；本地字符上限只是额外保险。
- 异地 Hub 之间暂不自动同步；同一局域网可由一台 Hub 协调多台电脑。
- 当前任务在安全节点停止或失败后可重试，但不承诺从 FFmpeg 已编码帧位置继续。

## 常见问题

**界面无法打开或白屏**

确认已安装 Microsoft Edge WebView2 Runtime，并从 PowerShell 启动查看错误。源码模式可使用 `scripts\run_dev.ps1 -Debug`。

**提示没有找到 FFmpeg**

网页不会在浏览器进程里运行 FFmpeg；它显示的是当前员工电脑本机制作服务的检测结果。先打开完整发布目录中的 `StoryForge Studio.exe`，用账号密码登录，等待软件自动连接当前电脑后刷新网页。如果本机服务已连接仍提示缺少 FFmpeg，再运行 `admin-tools\diagnose_storyforge.cmd`。源码模式可重新安装 `requirements.txt`；程序优先使用环境变量 `STORYFORGE_FFMPEG` 指定的 FFmpeg，其次使用系统 PATH，最后使用 `imageio-ffmpeg` 自带版本。`admin-tools\enable_storyforge_worker.cmd` 只供管理员在自动服务损坏时修复，不是首次使用步骤。

**硬件编码失败**

更新显卡驱动。自动模式会做一次短探测，但远程桌面、驱动更新和显卡占用仍可能影响编码器；如需强制 CPU 编码，请关闭软件，把 `<StoryForgeData>\settings.json` 中 `settings.video_encoder` 改为 `libx264` 后再启动。

**本地 Kokoro 提示未安装**

先确认网页已经连接当前员工电脑的本机制作服务；未连接时页面无法准确判断该电脑的配音运行时。连接后若仍显示“当前是轻量版，未内置 Kokoro”，请改用 Edge TTS/Deepgram、填写 Kokoro HTTP 地址，或安装 `-WithLocalAI` 完整版。源码模式应把 `requirements-ai.txt` 安装进启动本机制作服务的同一个 Python 环境。完整版还应确认同级存在完整的 `local-ai\kokoro` 目录；轻量 EXE 不能读取另一套 Python 环境中的 Kokoro。

**网页端必须一直打开 StoryForge 完整窗口吗？**

不需要。每台制作电脑首次打开 EXE 并输入员工账号密码后，软件会自动注册当前 Windows 用户的本机制作服务。随后可关闭完整窗口；网页仍通过 loopback 本机制作服务使用这台电脑的素材、TTS、FFmpeg 和输出目录。Hub 主机的团队网页是另一项服务，不能代替员工电脑的本机制作服务。

**其他电脑生成候选配音提示 `client has been closed` 或无法下载模型**

这通常表示只复制了 EXE、当前语种所需的离线模型/声线文件缺失，或目标电脑无法访问模型下载服务。重新复制整个发布文件夹，并核对 `local-ai\kokoro` 下的模型、配置和目标 Voice 文件。程序会优先使用这组本地文件；HTTP 客户端关闭等可重试错误也会重建会话后再试一次。

**云端任务中途回退后仍失败**

回退并不自动安装 Kokoro。先安装本地 AI 依赖或配置 Kokoro HTTP 地址，再重新加入任务。
