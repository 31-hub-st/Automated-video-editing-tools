# StoryForge Studio V2 产品需求基线

更新日期：2026-08-01
适用源码版本：StoryForge Studio `0.4.7`
状态：当前测试版需求基线
目标语言：美式英语仍是默认生产语言；小说库支持多语种自动识别与分类，本地配音已覆盖九个语言档案

## 1. 产品目标

StoryForge Studio 是一套 Windows 本地优先的小说推文视频生产工具。使用者导入小说正文、故事简介、小说封面、推广平台和推广口令，软件自动完成文稿整理、分集、钩子与悬念处理、女声旁白、对应语种字幕、视频素材、背景音乐、推广口令卡、浏览器即时预览和批量完整成片。

核心业务结果：

1. 提高前 30 秒留存，让用户愿意继续观看。
2. 保持剧情准确完整，只删重复句，目标保留原文 85%–90%；无重复时允许更高。
3. 让用户准确下载或打开对应小说平台，并输入指定口令继续阅读。
4. 多台电脑可同时生产，不重复生成任务，失败任务不阻塞其余任务。
5. 将小说、平台、口令和发布账号沉淀为固定资料库，将每次制作方案、完整成片和记录独立留档；历史 preview 产物继续可读但不再由新批次创建。

## 2. 已锁定的业务术语

- 软件账号：登录 StoryForge 的管理员或员工账号。
- 发布账号：人工发布视频使用的 TikTok 等账号；第一阶段不保存登录密码、不自动登录或上传。
- 小说推广平台：GoodNovel、MotoNovel、Novel Master 等承载小说和口令的平台。
- 小说平台绑定：一部小说在某个推广平台上的资料、引导语和最多 5 个历史口令。
- 原始章节：用户导入正文中识别到的章节，永久保留原始顺序和内容版本。
- 文案分集：正文中以 `Chapter`、`Episode`、`Part` 等显式标题标出的内容单位，保持原始顺序并作为制作台的一级可选单位。
- 资料库规划片段：导入时，显式分集预计超过 10 分钟可在完整句子或自然悬念点规划为多个可选子段；正文没有显式分集标题时，由软件按全文长度规划可选段。这里仅形成制作台可选单位，不代表提交批次时自动拆成多条视频。
- 固定资料：资料库中的小说正文/简介/封面/分集、推广平台模板、历史口令和发布账号；可供多个批次反复选择。
- 本批制作方案：一部小说 + 一个推广平台 + 用户本次手选口令 + 可选发布账号 + 分集范围 + 生成总视频数 + 本批女声/WPM/字幕/素材/音乐/输出设置。
- 批次：一次保存并提交的本批制作方案。一个批次只处理一部小说和一个推广平台，并拥有独立、稳定的 `batch_id`、冻结配置、持久化目标总数和进度汇总。
- E001/E002：仅用于软件后台、文件夹和文件名，成片画面不显示集数或总集数。

## 3. 资料库与小说资料

### 3.1 小说主档

每部小说保存：

- 内部 ID、标题、别名、自动识别/人工确认的语种、识别置信度、题材标签和状态。
- 故事简介；支持粘贴、TXT 和 Word（DOCX）导入。
- 正文内容版本、源文件、正文指纹和重复检测结果。
- 原始章节树、显式文案分集、必要的长集拆段，以及每个制作片段对应的原文范围。
- 小说封面原图和竖屏预览；资料库卡片与详情优先显示上传封面，只有未上传封面时才显示占位图。
- 已绑定的推广平台和该绑定下的历史口令。
- 最近制作时间、失败与质量提醒；具体配音、字幕、素材和输出参数保存在各批次中，不锁定在小说主档。

第一阶段以人工录入、TXT/Word 上传为主，不自动抓取推广平台页面。

### 3.2 导入与去重

- 支持单个 TXT、DOCX 和粘贴正文。
- 文件名中的推广口令允许字母和数字，不再要求纯数字。
- 使用标准化正文哈希识别“文件名不同但正文相同”。
- 重复正文默认提示复用现有小说，不静默创建副本。
- 正文更新创建新内容版本，历史成片继续引用旧版本，不覆盖历史。
- 自动语种识别只分析正文，不根据文件名或标题猜测；支持英语、简/繁中文、西班牙语、葡萄牙语、印尼语、法语、德语、意大利语、印地语、日语和韩语。证据不足或明显多语混排分别标记为“未识别”或“混合语种”。
- 资料库根据实际内容动态提供语种筛选和数量；低置信度结果醒目标记，管理员可人工纠正或要求重新检测。
- TXT 导入兼容 UTF-8/UTF-16、GB18030、Shift-JIS 和常见西文编码；二进制文件和明显乱码必须拒绝入库。
- 人工确认的语种在后续正文版本中保持生效，系统可以更新检测建议但不得静默覆盖人工选择。

### 3.3 原始章节与视频分集

- 章节标题不朗读、不显示字幕，只加入短暂停顿。
- 正文存在显式 `Chapter`、`Episode`、`Part` 等分集标题时，每个分集必须保持为独立可选单位；短集不得跨章静默合并。
- 导入资料库时，单个显式分集预计超过 10 分钟，软件可在场景、冲突、决定、揭示或悬念处规划可选子段，并在界面中归入同一个原始分集。用户随后决定选哪些子段一起制作。
- 正文没有任何显式分集标题时，软件才根据全文长度、完整句子和自然悬念点自动规划制作分集。
- 预计时长必须按实际文字脚本计算：拉丁文字按完整 Unicode 词计数，日语按汉字与假名、中文按汉字、韩语按韩文字母的等效朗读单位估算，不能只统计空格分隔的英文单词；TTS 完成后仍以真实 WAV 时长为准。
- 不在一句话、对话、动作或因果关系中间切断。
- 视频长度由用户本批所选内容决定；所选分集合计预计超过 10 分钟时只显示非阻塞提醒，仍合成为一条连续视频，不自动拆分，也不通过压缩语速强行缩短。
- 分集规划必须检查原文覆盖完整、顺序正确、无漏段、无跨集重复。
- 上集回顾按本批所选内容判断：从第 1 集开始时不生成；从后续集/子段开始时只在整组合并内容的开头生成一次 8–12 秒回顾。组内分集之间不得重复插入回顾；回顾只使用已发生剧情，不剧透、不编造。
- 上集尽量结束在自然悬念点；画面不显示 `Part 2 of 5` 或 `Episode 2`。

## 4. 推广平台与口令

### 4.1 平台档案

每个平台保存：

- 平台英文名。
- 屏幕常驻口令模板，例如 `Search GoodNovel: B73165`。
- 精确访问动作和结尾旁白模板，例如下载 App、打开小程序或输入口令。
- 可选平台 Logo 与品牌色；Logo 属于平台固定资料，不从某一本小说封面冒充提取，品牌色在 Logo 缺失时用于首字母占位和简介卡视觉统一。
- Hub 模式下，平台 Logo 保存为受控附件 URI，由主电脑分发并在制作电脑渲染前缓存为本地文件；平台记录和成片不得依赖主电脑的绝对路径。

九个平台的身份核验与官方应用商店入口见 [PLATFORM_LOGO_SOURCES.md](PLATFORM_LOGO_SOURCES.md)。应用商店页面只用于确认品牌身份和取得官方图标参考，不自动授予商标再使用许可。

第一阶段不保存 CPS、分佣比例、项目有效期或推广项目说明。

### 4.2 小说平台绑定

- 小说绑定平台后，可在该绑定下维护口令；封面、标题和故事简介仍来自小说固定资料，口令卡与结尾引导来自平台模板。
- 每个“小说 × 推广平台”历史累计最多领取 5 个口令；失效口令也计入累计，不可硬删除。
- 口令可启用、停用或标记失效。
- 每个批次由使用者手动选择口令。
- 后续批次可手动更换口令；软件保留历史快照并提示与上一批不同。
- 画面口令、旁白口令、封面结尾 CTA 和制作记录必须读取同一份不可变快照。

## 5. 一页制作台与批次方案

- 一个批次只处理一个推广平台和一部小说。
- 制作台在一个页面完成小说、平台、口令、发布账号、分集、生成总视频数、女声、WPM、背景音乐音量、字幕、封面动效、渲染模式、视频素材目录、音乐目录和输出目录的选择。
- 可选择一个或多个文案分集，并直接填写本批生成总视频数。所选分集按正文顺序合并成一个连续内容单元；总视频数表示该合并内容要生成的去重版本数量，不得再按分集拆开或均分。
- 选择从第 1 集开始时不生成上集回顾；从后续集开始时只在整组开头生成一次回顾。生成数量不设置每集 10 条或其他业务上限。超大批次使用磁盘计划、分块持久化和有界内存窗口；界面不要求员工理解内部变体编号。
- 发布账号可从资料库选择，也允许保持“待分配”。
- 人工发布后可回填发布账号和发布数据。
- 每批从 3 个候选中选择一个统一女声，本批所有分集和视频保持该 Voice ID；下一批允许重新选择，不改写小说固定资料。
- 同一批的多条视频可使用不同的事实准确钩子、解压素材和起始点，但本批确认的女声、字幕方案、平台和口令保持一致。
- 保存批次时冻结一份不含密钥的制作配置快照。修改女声、WPM、字幕、音乐或画面参数后保存草稿，浏览器即时预览随之更新；点击生成后直接创建完整视频任务，不存在再次审批。
- 提交成功后，制作台必须立即脱离已经冻结的草稿并创建一个没有草稿 ID 的下一批；不得要求员工等待上一批完成，也不得允许后续编辑修改已提交任务。
- 下一批沿用同一小说、平台、题材、目标数量、女声、WPM、音乐音量、字幕/画面样式、封面设置、渲染模式和本机视频/音乐/输出目录；必须清空并重新选择口令、发布账号和分集。员工仍可手动改动任何被沿用的本批设置。
- 同一制作电脑允许连续提交任意多个批次。批次严格按提交顺序 FIFO 执行；超大批次尚未装入内存的持久化尾部仍属于该批，后续批次不得越过。失败任务记录失败阶段和原因，成为终态后自动跳过；同批剩余任务和后续批次继续执行。

员工可见输出目录固定为一个批次一个平铺文件夹：

`待发布/<平台>_<口令>_<小说>_B<批次8位>/`

常规视频生成（兼容枚举值 `video_and_mp3`）每条任务只交付最终 MP4，不再额外导出旁白；`audio_only` 只交付最终纯旁白 MP3；`reuse_audio` 复用员工选择的可靠旁白 MP3 更换视频素材，只交付新的最终 MP4。文件名必须包含批内序号、平台、口令、E001/E002、变体号和批次短 ID，便于排序、批量复制和人工发布且不会互相覆盖。日志、Manifest、ASS、内部 WAV、原稿、渲染命令、恢复信息和缓存不得混入员工可见发布文件夹，统一写入用户首次选择的 `<StoryForgeData>` 数据根目录。

## 6. 文稿策略

- 英语正文只做英语润色；其他已确认语种保持原语种，不得静默翻译成英语。
- 删除重复句，预计保留 85%–90% 剧情；原文无重复时不为满足比例而强删。
- 允许改善翻译腔、标点、断句和英文阅读节奏。
- 允许 AI 根据故事生成不同开头钩子。
- 固定开场结构，但钩子内容随小说变化。
- 成人表达提供两个设置：`保留直接表达`、`更具吸引力`。
- 不编造关键事实、人物关系或结局。
- 结尾在自然悬念处收束，并由旁白念出精确平台与口令引导。
- 标题文案、TikTok 描述和标签暂不进入第一阶段自动生成范围。

## 7. 配音

- 默认美式英语女声，不使用多角色配音。
- 每批可用真实正文片段生成 3 个候选女声试听。
- 题材、人物年龄感和情绪影响候选声线，真人感优先。
- 使用者选定后，本批所有分集和视频保持同一 Voice ID；重新建立下一批时仍可手动更换。
- 声音不可用时任务暂停/失败并明显提示，不得静默换声。
- 本地 Kokoro 与云端 TTS 可在设置中切换；优先免费/本地，允许未来少量付费额度。
- 免费本地 Kokoro 支持 `en`（美式英语）、`en-gb`（英式英语）、`ja`、`es`、`fr`、`hi`、`it`、`pt-br` 和 `zh`；制作台只显示对应语种真实存在的女声，数量不足 3 个时不得用重复或错误 Voice ID 补齐。
- 日语本地前处理依赖 `pyopenjtalk-plus / fugashi / jaconv / mojimoji / unidic-lite`，中文依赖 `misaki[zh]` 的分词与拼音组件；离线发布版必须把依赖和对应 Voice 文件一起交付。
- Deepgram 当前提供英语候选，并为日语提供 `Izanami / Uzume / Ama` 三个候选；使用云端前必须配置有效额度和 API Key。
- Edge TTS 是无需 API Key、但必须联网的可选制作电脑客户端；通过实时上游目录覆盖 `en / ja / es / fr / de / id / ko / it / pt-br / hi`。只有组件已安装且查询到真实 Female Voice 时才显示候选，最多 3 个，不能缓存虚构 ID 或用英语声线代替失败语种。
- 印尼语、德语、韩语可选择 Edge TTS；未识别、混合语种、组件缺失或上游无女声时仍不得静默套用英语音色，必须先确认语种或更换兼容 Provider。
- 目标语速可在制作台调整，当前界面范围为 160–250 WPM；不得为塞入全文无限压缩语速。
- 建立人名、地名、平台名和口令发音词典。
- 先生成自然连续旁白，再根据真实音频对齐字幕；不得按每条字幕独立合成导致语气破碎。
- 旁白和对齐文件允许保存到 Hub，以供多台电脑复用。

## 8. 字幕

- 英文字幕按语义短语和自然停顿切分，不照搬中文逐字断句习惯。
- 常规每条 3–8 个英文单词、最多两行；不拆人名、短语动词、否定结构或冠词与名词。
- 字幕根据旁白真实时间对齐，允许为阅读节奏重断句。
- 提供多套经验证的字幕预设：清晰描边、电影阴影、极简阅读和强力戏剧。
- 字体、字号、颜色、描边、位置和模板可预览调整。
- 默认无字幕入场动画；可选轻量动画，但必须保持稳定易读。
- 不做重点词变色的默认效果。
- 自动检测 TikTok 安全区域、换行、水平居中和越界；越界时自动调整。
- 顶部口令卡全程固定展示，不做花哨动画。

## 9. 画面、封面与音乐

- 视频模式输出 9:16、1080×1920、默认 60 FPS、MP4、H.264；低配置或兼容场景可切换 30 FPS。默认 `output_mode=video_and_mp3` 代表“常规视频生成”，只交付完整 MP4；显式 `output_mode=audio_only` 时只交付 48 kHz、192 kbps 纯旁白 MP3；`output_mode=reuse_audio` 复用已有可靠旁白 MP3 更换素材，只交付新的完整 MP4。
- 一条视频优先使用一个足够长的新素材；不够时拼接新素材。
- 始终删除素材原声。
- 横版或比例不符素材使用模糊背景，完整保留主体画面。
- 唯一素材用完后允许镜像、裁切、改变起始点和轻微变速。
- 直接显示每个素材的使用次数，不设强制阻断阈值。
- 视频素材不按小说题材自动匹配。系统只递归扫描员工本批手动选择的视频素材目录，并在其中按去重、时长和可解码性选择素材；该目录没有可用视频时才失败。小说题材只用于文稿、声音和运营分析，不参与视频目录选择。
- 允许素材循环，但优先使用足够长的新素材。
- 背景音乐按题材自动匹配，自动避让旁白；默认可听见但不得盖过人声。
- 资料库卡片、小说详情和制作台均优先显示已上传的小说封面；未上传封面时才使用系统占位图，不得让占位图覆盖真实封面。
- `platform_story_card` 前 5.5 秒使用社交平台信息卡布局：平台 Logo/名称和精确口令位于票据头部，品牌色作为视觉强调，正文显示真实故事简介或分集摘录，最多 5 行；不得用廉价渐变占位或把小说封面水印误作平台 Logo。
- 平台 Logo 是独立平台资产，优先使用平台提供的透明 PNG/SVG 或官方应用商店图标；临时从已授权推广截图裁切时必须保留来源记录，之后可在平台档案中无损替换。
- 小说封面可在钩子后随旁白舒适淡入/轻推近；结尾封面为本批和生产预设中的可选项，默认开启。
- 封面动画不使用快速放大、闪烁或遮挡字幕。

## 10. 可选封面结尾

- `cover_outro_enabled` 默认 `true`。开启时每条视频最后预留 5–7 秒，由小说真实封面铺满 1080×1920 全屏，不再叠加白色平台卡片。
- 关闭时不使用小说封面及其动画，保持正文画面完成结尾；CTA 旁白、字幕和顶部搜索口令仍正常持续。
- 封面保持正确比例：允许中心裁切、智能主体避让或模糊延展，不允许拉伸变形、偏移出画面或露出粗糙黑边。
- 提供无动画、淡入、轻推近、轻拉远、慢速平移和柔和视差等可选动效；动效参考常见剪辑软件的舒适节奏，不快速缩放、不闪烁。
- 结尾 CTA 由旁白念出，并使用本批当前的普通字幕或逐词字幕样式同步显示；不另做独立平台文案卡。
- 顶部搜索口令卡持续显示到视频结束，口令、旁白、字幕与制作快照必须完全一致。
- `FINAL PART` 只允许出现在当前正文版本按完整顺序计算的真正最后一集；仅仅是本批已选分集中的最后一项或最后生成的一条变体，都不能被误判为全书最终集。

## 11. 即时预览与直接生成

- 桌面制作台、Hub 团队网页和制作电脑本地网页都提供开头、正文字幕、封面结尾三态的 HTML/CSS 即时预览；选择模板、字幕、颜色、位置或封面动效后，右侧预览立即更新。
- 即时预览不生成 MP4、WAV、ASS 或生产记录，只用于快速检查构图、安全区、字幕样式和结尾设计；它不是逐帧渲染结果。
- 真实女声效果通过制作电脑本机制作服务生成并试听候选音频确认；桌面窗口、Hub 网页和该电脑的 loopback 本地网页都可发起相同操作，但媒体计算必须落在当前电脑的本机制作服务，不能由普通浏览器或 Hub 进程直接执行。启用本机制作服务后完整桌面窗口无需常开。
- 配置确认后，在制作电脑点击“直接生成完整视频”，一次创建 `job_kind="full"`、`status="queued"` 的全部任务，并返回 `preview_required=false`；不再设置独立审批步骤。
- 修改女声、WPM、字幕、音乐、素材、封面或渲染模式后，保存当前草稿；即时预览随配置更新，之后可直接重新创建完整任务。
- `output_mode` 有 `video_and_mp3`、`audio_only` 与 `reuse_audio` 三个合法值。为兼容旧客户端，`video_and_mp3` 名称保留但语义为“常规视频生成”，只交付完整 MP4；`audio_only` 跳过视频渲染，只交付 48 kHz、192 kbps 纯旁白 MP3；`reuse_audio` 读取员工选择的可靠旁白 MP3，跳过文稿改写、TTS 和字幕重新对齐，只更换视频素材并交付新的完整 MP4。
- 旧 `export_narration_audio=true`、`false` 或字段缺失都安全迁移为 `output_mode=video_and_mp3`，即当前常规视频模式；新任务不会因此额外生成 MP3。只有显式选择 `audio_only` 才交付纯旁白，只有显式选择 `reuse_audio` 才复用已有旁白。
- 员工发布目录按批次平铺：常规视频生成和已有配音更换素材只包含最终 MP4；仅生成配音只包含最终 MP3。Manifest、日志、ASS、内部 WAV、原稿、渲染命令、恢复信息和缓存属于技术产物，统一保存在用户选择的 `<StoryForgeData>\render-work\<批次>\<任务>\` 等数据目录；旧任务原有目录仍兼容读取。

### 11.1 历史 preview 兼容

- `job_kind="preview"`、`previewing`、`awaiting_preview_approval`、旧批准/重做实现及历史产物只作旧数据解码和迁移兼容；当前 UI、Hub 网页和制作电脑本地网页均不开放这些接口，通用重试也拒绝历史 preview。
- 当前 UI 不再为新批次创建 preview，不以历史批准状态作为完整任务的生产门槛。
- 嫁接其他系统时可迁移或只读展示历史 preview，但不得把它重新引入当前主流程。

## 12. 发布账号与运营记录

第一阶段不自动登录或上传 TikTok，但提供发布账号库和人工回填：

- 账号名称、发布平台、地区、内容定位、备注、状态。
- 待发布、已发布集数、最近发布时间。
- 可将成片保持“待分配”，发布后再绑定账号。
- 后台既显示成员工作量，也显示发布账号的视频归类与表现。
- 支持人工录入浏览、点赞、评论、口令转化和收益数据。
- 同一小说的分集归类清晰，但发布账号仍可保持“待分配”，不强制自动分配。
- 制作台任务胶片带以 `batch_id` 聚合为“批次卷宗”，默认折叠单视频明细；卷宗摘要显示数据库持久化的目标总数、总体状态、进度和成功/失败数量。展开后可查看与操作单条视频，并跳转到该批次/单视频的生产记录。返回给界面的任务卡可能只是有界窗口，产品不得用可见卡片数推断整批总数、进度或是否完成。归档和恢复保持批次层级，不删除本机文件。

## 13. StoryForge Hub 与权限

### 13.1 部署

- 同一局域网指定一台电脑长期运行 StoryForge Hub。
- 多台制作电脑通过 Hub API 共享业务数据，不能直接并发打开同一个数据库文件。
- 异地电脑运行独立 Hub，功能一致但不自动同步制作记录。
- Hub 保存固定资料库、用户、草稿、任务元数据、租约、生产记录、产物校验信息和本机受控引用；媒体执行队列位于各制作电脑本机。完整 MP4、纯旁白 MP3、历史预览、内部 WAV、ASS 和字幕对齐文件始终不上传 Hub，管理员也不能开启该能力。
- 原始大视频和全部生产产物只保留在生成电脑；Hub 不保存、代理或跨机读取这些文件，也不为新批次生成代理 preview。
- 核心程序通过完整 ZIP 自动检查、下载并在空闲安全重启时安装；语言资源使用独立组件更新，安装到 `<StoryForgeData>\components`，逐文件校验、原子切换并保留上一版回退。当前 `0.4.7` 完整包仍内置日语链路。
- Hub 固定资料快照位于 `<StoryForgeData>\hub-backups`，保留 72 小时且最多 3 份，内容摘要相同则去重。管理员整库恢复必须先关闭 StoryForge，再运行 `admin-tools\restore_hub_backup.cmd`；文件选择器优先选择 `.sfbak`，也兼容带完整 StoryForge 清单的旧 `.zip`，可直接选择从其他电脑复制到任意合法目录的备份。恢复器会在写入前校验文件类型、清单、每个文件的 SHA-256 和压缩包路径安全性，随后自动创建 `pre_restore` 快照，再以所选备份整体覆盖小说、平台绑定、全部口令、设置/预设及其他 Hub 固定资料，不做合并，也不触碰员工电脑的视频素材、最终成品或渲染缓存。

### 13.2 软件账号与权限

- 两个角色模板：管理员、员工。
- 管理员负责资料、口令、批次、生产记录、成员账号、权限规则和 Hub；员工默认只处理自己的任务与记录。
- 管理员可对每个账号单独开启或关闭高级权限；高级权限在界面中默认折叠，用于少量例外，不再设置中间岗位。
- 权限包括：小说编辑、平台/口令管理、发布账号管理、任务创建、查看全部记录、重试/取消他人任务、导出记录、用户管理、Hub 管理。旧 `samples.approve_*` 权限只保留为隐藏的历史兼容项，不进入当前角色说明。
- 制作电脑的发布包预置 Hub 地址。首次打开 EXE 只输入成员账号和密码；软件自动读取 Windows 电脑名称、登记设备、安全保存内部设备凭据并启用后台制作服务。界面不提供令牌登录、生成、复制或旧令牌连接入口。新员工默认密码为 `xs123456`，首次登录后建议修改但不强制，也不作为验收门槛。
- 至少保留一个启用的管理员账号，防止所有账号被锁定。
- 权限、口令、正文和关键任务操作写审计记录。

### 13.3 并发与断网

- Hub 通过任务租约和心跳避免两台电脑重复制作同一任务。
- 当前已领取的渲染在 Hub 暂时断开后可继续，本地排队等待回传状态。
- 断网期间不允许创建新共享批次或修改共享小说资料。
- 单个任务失败不会停止队列，软件内显示显眼汇总；不使用 Windows 系统通知。

### 13.4 制作电脑本地网页与 Hub 浏览器边界

- Hub 浏览器用于共享资料库、平台与口令管理、草稿准备、HTML/CSS 即时预览、记录和产物元数据查看及后台管理。只有页面运行在已绑定并启用 Local Worker 的当前员工电脑上时，才可通过该电脑的 loopback 服务打开本机成片并完成全部生产操作；管理员在其他电脑不能通过 Hub 播放或下载员工本地成片。
- 安装完整 StoryForge 的制作电脑负责候选配音、本机素材与输出目录、直接创建完整任务、队列控制、失败重试和 FFmpeg 渲染；同一能力可由桌面窗口、Hub 页面连接的本机制作服务或当前电脑的 `127.0.0.1:18765–18770` 本地网页调用。本机服务可注册为当前用户登录任务，完整窗口无需常开。
- Hub 进程通过 `WEB_DESKTOP_ONLY_MEDIA_METHODS` 拒绝直接执行媒体 RPC。本机白名单覆盖候选配音、Kokoro/Edge 免费 TTS 切换、目录、完整建队、队列控制、查询、取消、重试、归档/恢复/分页历史和打开输出；历史 preview 的批准/重做方法不开放。
- 本地网页只监听 loopback，校验 Host/Origin 防止 DNS rebinding，并在每个 RPC 重新校验 Hub 账号、设备、权限和所有权；跨电脑保存的绝对路径不会被直接继承。
- 该限制是运行端隔离，不是账号权限不足；管理员权限也不能让 Hub 进程直接访问制作电脑的本地素材、GPU 或 Kokoro。管理员不参与员工文件夹配置。

## 14. 性能

- 当前电脑采用一个完整 FFmpeg 渲染流，同时后台准备下一任务的文本、TTS 缓存和素材探测。
- 自动检测编码器；优先使用可用硬件编码，失败时回退到兼容模式并记录原因。
- 同一批多条视频复用旁白、字幕对齐、素材探测和中间文件，避免重复计算。
- 提供浏览器即时预览，以及速度优先、质量优先和兼容模式的完整成片渲染。
- 多台电脑同时运行时由 Hub 去重，不强制第一阶段跨电脑自动调度素材任务。

## 15. 自动质量检查

- 正文覆盖完整，无漏段、无错序、无无意重复。
- 回顾仅包含已发生事实。
- 同一批确认配置中的 Voice ID 一致，成片不得静默换声。
- 字幕与语音同步、英文切分自然、水平居中、无安全区越界。
- 平台、小说、封面和口令绑定一致。
- 口令在顶部口令卡、旁白、封面结尾 CTA 字幕和记录中完全一致。
- 检查黑屏、静音、削波、字幕越界、封面拉伸、输出损坏。
- `audio_only` 检查 MP3 可播放、采样率为 48 kHz、目标码率为 192 kbps、时长与本次旁白一致，并确认不包含背景音乐和素材原声；`video_and_mp3` 与 `reuse_audio` 检查最终 MP4 可播放且通过视频质量检查，并确认员工发布目录没有额外生成旁白 MP3。
- 最终成片参数与冻结的制作方案及 Manifest 保持一致。
- 失败任务记录具体阶段、错误和修复建议。

## 16. 第一阶段不做

- 自动登录、自动上传或自动发布 TikTok。
- TikTok 平台合规检查。
- 自动抓取推广平台页面或自动申请口令。
- 自动生成发布描述和标签（等待后续单独需求）。
- 异地 Hub 之间实时同步。
- 自动登录、自动分配或强制绑定发布账号。

## 17. 第一阶段验收主流程

1. 管理员建立推广平台和成员账号，并为每人选择管理员或员工角色。
2. 导入 TXT/DOCX 或粘贴一部英文小说与简介，重复导入得到去重提示。
3. 软件识别正文中的显式 `Chapter`、`Episode`、`Part` 等分集并保持独立；导入阶段可把超过 10 分钟的原始分集规划为可选子段，无显式标题时才按全文规划。制作台以用户勾选结果为准：所选分集合计超过 10 分钟只提醒，不自动拆分。
4. 在资料库为小说绑定推广平台并录入不超过历史累计 5 个口令；可选登记人工发布账号。
5. 员工在制作台选择小说、本批平台与口令、发布账号、一个或多个分集/子段和生成总视频数；所选内容按正文顺序合成一条连续视频的内容单元，再按生成总数制作对应去重版本，不能按分集分别成片。生成数量不设业务上限。
6. 在同一页试听 3 个美式女声并选择本批统一女声，设置 WPM、音乐音量、字幕、素材/音乐目录和输出目录。
7. 使用开头、正文字幕、封面结尾三态即时预览检查样式；真实女声可在桌面窗口、连接本机制作服务的 Hub 网页或本机网页试听，预览过程不生成媒体文件。
8. 在制作电脑直接创建完整任务，任务以 `full + queued` 进入本机队列且 `preview_required=false`；视频素材只从员工本批选择的目录递归扫描，不按小说题材自动匹配；单项失败被跳过，其余继续。
9. 排队成功后，制作台立即显示下一批的新草稿：保留女声、样式、节奏和本机目录，清空口令、发布账号与分集。员工无需等待，可连续提交至少三个不同批次；实测执行顺序与提交顺序一致，第一批的流式尾部不会被第二批插队，失败项不阻塞后续批次。
10. 输出按小说、平台口令、批次和 E001/E002 归档，并记录素材使用次数；制作台按 `batch_id` 显示可折叠批次卷宗，使用持久化总数和总体进度，展开单视频可跳生产记录。
11. 管理员可在“设置 → 多电脑协同”查看、命名和停用任意数量的制作电脑；制作电脑通过账号密码自动登记。制作默认值统一由团队默认模板管理，不再另设设备级“下发制作默认值”。Hub 可查看任务、生产记录、成员工作量及待分配产物的元数据，但不能读取、播放或下载员工本地成片；本地配音与渲染始终由各制作电脑承担。
