# StoryForge Studio 0.2.0 发布与嫁接摘要

> 冻结日期：2026-07-24  
> 应用版本：`0.2.0`（`storyforge.__version__`）  
> Windows 入口：`StoryForge Studio.exe`  
> 详细设计：[STORYFORGE_INTEGRATION_REPORT.md](STORYFORGE_INTEGRATION_REPORT.md)  
> 安装协同：[DEPLOYMENT_WINDOWS.md](DEPLOYMENT_WINDOWS.md)  
> 更新协议：[AUTO_UPDATE.md](AUTO_UPDATE.md)

## 1. 本版交付能力

- 小说 TXT/DOCX/粘贴导入、正文去重、不可变版本、自动语种/题材识别、显式章节和自然分集。
- 小说、平台、最多 5 个历史口令、人工发布账号、封面/Logo 的长期资料库。
- 一个批次一部小说、一个平台，可选择任意分集和生成总数；最多 3 个真实女声候选，30 秒样片通过后全量。
- 本地/云文本与 TTS、真实 WAV 句/段时长、ASS 字幕、素材去重、音乐 ducking、H.264 1080×1920 60/30 FPS。
- `classic` 与 `platform_story_card`；小说简介卡可使用真实简介或有事实约束的 AI 增强。
- 四类可编辑视觉系统：简介卡、正文字幕、顶部搜索口令卡、结尾卡；共 19 个内置预设（7+4+4+4），支持全局默认、本批覆盖、任务冻结。
- `word_pop_sync`：字幕按旁白句/段时长依次变色和弹出。
- 管理员/员工、账号级权限覆盖、Hub Token、局域网 Catalog/附件/租约协同。
- Hub 发布完整 ZIP；制作电脑默认每 60 秒轮询并自动下载、校验，用户安排重启后安全安装，渲染忙时延后。

明确不包含：TikTok 登录/上传/发布、平台合规检查、推广口令自动申请、跨地点双 Hub 同步、远程通用 Worker 调度。

## 3. 稳定数据与 API 合同

### 3.1 桌面桥接外壳

```json
{"ok": true, "data": {}}
```

```json
{"ok": false, "error": "可显示给用户的错误"}
```

当前桥接方法未带正式 `/v1` 版本号。嫁接到其他程序时应在外部新增版本化 DTO/HTTP Adapter，不要把所有 `StoryForgeApi` 公共方法直接暴露到公网。

### 3.2 关键桌面方法

| 能力 | 方法 |
| --- | --- |
| 初始化 | `get_bootstrap`, `get_library_bootstrap`, `get_novel` |
| 小说 | `import_novel_text`, `import_novel_file`, `save_novel`, `classify_novel` |
| 平台/口令/账号 | `save_platform`, `save_novel_binding`, `add_promo_code`, `update_promo_code`, `save_publishing_account` |
| 女声/批次 | `generate_voice_candidates`, `lock_novel_voice`, `save_production_draft`, `queue_production_draft` |
| 样片/队列 | `approve_preview`, `regenerate_preview`, `retry_failed`, `start_queue`, `cancel_queue`, `get_jobs` |
| 样式 | `get_visual_style_presets`, `save_settings`；批次样式写入 `production_settings` |
| 团队 | `save_software_user`, `set_user_permission`, `issue_hub_user_token`, `revoke_hub_user_token` |
| 更新 | `get_update_status`, `check_for_updates`, `download_update`, `schedule_update_on_restart`, `cancel_scheduled_update`, `publish_update`, `clear_published_update` |

`get_bootstrap().data` 包含 `settings / platforms / batches / jobs / system / catalog / hub_status / update_status / visual_style_presets`。

### 3.3 视觉方案合同

```json
{
  "subtitle_preset": "word_pop_sync",
  "intro_card_preset": "editorial_white",
  "code_card_preset": "brand_pill",
  "outro_card_preset": "brand_focus",
  "subtitle": {
    "word_sync_enabled": true,
    "unread_color": "#D0D5DD",
    "active_color": "#FFE06A",
    "read_color": "#FFFFFF",
    "pop_scale": 112,
    "pop_duration_ms": 140,
    "pop_intensity": 0.65
  },
  "intro_card": {},
  "code_card": {},
  "outro_card": {}
}
```

预设：

- Subtitle：`clear_outline / cinematic_shadow / clean_minimal / bold_drama / reader_focus / soft_box / word_pop_sync`
- Intro：`editorial_white / cinematic_dark / romance_soft / minimal_clean`
- Code：`brand_pill / dark_glass / light_chip / outline_only`
- Outro：`editorial_white / cinematic_dark / brand_focus / minimal_clean`

以上合计 19 个内置视觉预设。当前冻结的 UI 契约基线为 26 项通过，桌面 UI 静态资源缓存查询版本为 `v19`；嫁接项目若替换前端，应把这些数字视为本次发布验收基线，而不是长期固定协议。

`get_visual_style_presets()` 返回解析后的完整字段；全局 `save_settings()` 持久化到当前电脑。制作台进入样式工作室后把完整快照写入草稿 `production_settings`，再冻结到 `RenderJob.settings_snapshot`。本机快捷预设只在浏览器 `localStorage` 的 `storyforge.visual-style-presets.v1`，不经 Hub 同步。

### 3.4 逐词字幕精度

系统使用 TTS WAV 的真实句/段时长建立外边界；语段内句子、语义短语、分页和单词时间按文本权重/显示宽度分摊。每个非重叠词窗重绘整页：过去词 `read_color`、当前词 `active_color + scale`、未来词 `unread_color`；CJK 按宽字符逐字。

这不是声学 forced alignment，也没有使用 Provider 原生 word timestamp。它可重复、首尾与音频段一致，但不应声称每个词与发音波形精确对齐。

### 3.5 Hub 更新 HTTP

| 请求 | 合同 |
| --- | --- |
| `GET /updates/manifest` | Bearer；`{"ok":true,"update":manifest或null,"signature":HMAC}` |
| `GET /updates/package?version=x.y.z` | Bearer；只返回当前公告版本，含 `Content-Length`、`X-Content-SHA256` |

Manifest Schema 1：

```json
{
  "schema_version": 1,
  "version": "0.2.0",
  "filename": "StoryForge-0.2.0-<sha12>.zip",
  "sha256": "64-hex",
  "size_bytes": 123,
  "entrypoint": "StoryForge Studio.exe",
  "release_notes": "...",
  "published_at": "ISO-8601"
}
```

常见更新状态：`idle / checking / up_to_date / available / downloading / downloaded / scheduled / deferred / applying_on_restart / error / publisher_idle / published / publish_error`。关键字段：`current_version / available_version / scheduled_version / progress / message / checked_at / package_path / downloaded / apply_on_restart / restart_required / rendering_busy / release_notes / published_at / error / published_update`。

## 4. Schema 与迁移基线

| 数据 | 当前版本 | 说明 |
| --- | ---: | --- |
| Catalog SQLite | 8 | V2 租约；V3 临时主管；V4 折叠为员工并保留覆盖；V5 语种；V6 分集规划；V7 多语种时长；V8 平台 Logo/品牌色 |
| `settings.json` | 10 | V8 默认 60 FPS；V9 四类可编辑视觉；V10 自动更新设置 |
| 成片/样片 Manifest | 2 | 任务、文本、TTS、素材、字幕、卡片、编码和质检 |
| Prepared text cache | 1 | 与 `recipe_hash` 绑定 |
| Production recipe | 1 | 草稿元数据中的 `recipe_version` |
| Update Manifest | 1 | Hub 权威发布清单 |
| Update package metadata | 1 | ZIP 根 `storyforge-update.json`；官方构建器写入 |
| Pending update marker | 1 | 客户端安排重启安装 |

迁移由新程序启动时执行。Hub 环境先备份并升级主电脑；新程序不要直接写 SQLite 或跳过 `CatalogRepository/SettingsRepository`。

## 5. 角色与标准工作流

- 管理员：维护小说/平台/口令/账号、成员和设备令牌；在主机管理 Hub 和发布更新；设置全局视觉默认。
- 员工：查看资料、使用口令、创建自己的批次、自由调整本批视觉、试听女声、审核/重试自己的任务。
- 账号级权限可 `allow / deny / inherit`。旧“主管”迁为员工并保留差异权限。

生产顺序：管理员维护长期资料 → 员工可视选书 → 选平台/口令/分集/数量 → 题材/女声 → 本批样式/素材/音乐 → 30 秒样片 → 审批 → 全量 → 失败项跳过并可重试 → 人工发布。

注意：UI 称 `save_settings()` 的视觉值为“团队默认”，但当前它落在**当前电脑**的 `%APPDATA%\StoryForgeStudio\settings.json`，不会自动通过 Hub 复制到其他电脑；真正跨电脑共享的是保存进 Catalog 草稿的本批快照。若嫁接项目需要团队级默认模板，应新增 Hub/Catalog `style_profiles` 实体和权限 API。

## 6. 推荐嫁接路线

1. 保留 `catalog + library_service + services + providers + pipeline`，先运行现有迁移和测试。
2. 为 Novel/Revision/Episode/Draft/Job/Record/Artifact/VisualRecipe 建立目标项目的版本化 DTO。
3. 用正式 `/v1` Adapter 替换 pywebview 桥接；文件改用资源 ID/对象存储 URI，不把任意本机路径暴露给远程调用。
4. 把 `PipelineRunner` 封装为 Worker；以成熟持久队列替换/包装 `JobQueue`，增加幂等键、事件、取消、超时和断点恢复。
5. 把目标系统账号映射到 StoryForge actor 与权限；不要启用当前预留但未完成的 `password_hash` 登录。
6. 如保留 Hub，继续使用 RPC 白名单和资源根约束；公网前必须加 TLS/VPN、限流、集中日志和独立发布签名。
7. 对相同小说做双跑，对比分集 ID、Voice、字幕/卡片、口令、成片和 Manifest；保留 5 口令、去重、样片门和失败继续测试。

推荐能力边界：

```text
新业务 UI/API
    ↓ versioned DTO adapter
CatalogRepository + LibraryService
    ↓ immutable ProductionRecipe
Persistent Queue
    ↓
PipelineRunner Worker
    ↓
Artifacts + Manifest + Record events
```

## 7. 构建、完整安装与更新包

### 构建本地 AI 版

```powershell
# 仅在源码根 local-ai\kokoro 尚未准备时先执行；已有完整资产可跳过。
& '.\scripts\export_kokoro_offline_assets.ps1' `
  -Destination '.\local-ai\kokoro' `
  -PythonExe '.\.build-venv\Scripts\python.exe'

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\scripts\build_exe.ps1" `
  -WithLocalAI `
  -OutputDirectory ".\release\StoryForge-Studio-0.2.0"
```

`-WithLocalAI` 会校验源码根 `local-ai\kokoro` 并自动复制到输出目录；资产不完整时构建失败，不再需要成功构建后手工再复制一次。

第一次安装必须复制整个目录到当前用户可写位置；不要只复制 EXE，也不要直接从 ZIP 运行。

### 制作更新 ZIP

```powershell
python .\scripts\build_update_package.py `
  ".\release\StoryForge-Studio-0.2.0" `
  --entrypoint "StoryForge Studio.exe" `
  --version 0.2.0 `
  --output ".\release\StoryForge-0.2.0-update.zip"
```

ZIP 根：

```text
storyforge-update.json
StoryForge Studio.exe
local-ai\kokoro\...
```

主机通过 `publish_update(path, version, notes)` 发布。客户端默认 60 秒轮询、自动下载和全链路校验；用户选择重启安装。安装器在桌面进程退出后重验摘要、隔离解压、备份并覆盖，复制失败回滚；不会删除新包未包含的旧文件。

### 验证

```powershell
python -m compileall -q storyforge tests
python -m unittest discover -s tests
node --check .\ui\app.js
& '.\release\StoryForge-Studio-0.2.0\StoryForge Studio.exe' `
  --kokoro-self-test '.\release\kokoro-check'
Get-FileHash -Algorithm SHA256 `
  '.\release\StoryForge-Studio-0.2.0\StoryForge Studio.exe'
```

## 8. 更新安全边界

- Manifest 以当前客户端 Bearer Token 做 HMAC-SHA256；包按大小、响应头和流式 SHA-256 多次校验。
- ZIP 拒绝绝对/父目录/重复路径、符号链接、入口或版本不一致、超过 20,000 条目或 8 GiB 解压体积。
- 下载先写 `.part`，校验后原子移动；渲染忙时不热替换。
- HMAC 不是发布者私钥签名；当前 Hub 默认 HTTP，Token 可能被局域网监听。只用于可信专用网络/VPN。
- 当前 EXE 未 Authenticode 签名；安装 Worker 非提权，安装目录必须可写。

## 9. 已知约束

- 逐词字幕是句/段真实时长内的确定性文本分摊，不是声学词级对齐。
- `JobQueue` 是单机内存串行队列；重启后记录变 `interrupted`，不会从 FFmpeg 中间断点恢复。
- Hub 是单 SQLite 权威点；不同地点的 Hub 不自动同步。
- 自动更新是 60 秒默认轮询，不是推送；下载后仍需安排重启，Hub 主机不自动更新自身。
- 更新器逐文件备份/覆盖，不是目录原子切换；不能通过省略文件删除旧组件，断电需人工完整包修复。
- 全局样式和本机快捷预设不在 Hub 中；跨电脑共享的是草稿冻结方案。
- 本地 Kokoro 仅覆盖随发布资产提供的语言/Voice；识别出一种语种不代表该 Provider 一定有对应 Voice。
- 当前桌面本地操作假设操作者可信；“仅管理员保存团队默认/发布更新”主要由产品流程和 UI 入口约束，本地 pywebview 桥接没有独立登录会话。嫁接时应把这些动作放到服务端权限强制层。
- 当前 Hub 无 TLS，桌面 API 未版本化，EXE 无正式 Windows 版本资源/代码签名。
