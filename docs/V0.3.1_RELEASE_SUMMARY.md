# StoryForge Studio 0.3.1 发布与嫁接摘要

> 发布日期：2026-07-25  
> 源码版本：`storyforge.__version__ == "0.3.1"`  
> Catalog Schema：9；Settings Schema：12；输出 Manifest：2；更新 Manifest：1  
> 完整架构与嫁接合同见 [STORYFORGE_INTEGRATION_REPORT.md](STORYFORGE_INTEGRATION_REPORT.md)。

## 1. 本版结果

0.3.1 集中解决三个生产问题：含英文撇号的书名会在 FFmpeg 字幕滤镜阶段失败；30 秒样片审核耗时偏长；任务多以后胶片带缺少整理能力。同时补齐制作台右侧样式预设的即时反馈。

- 默认样片改为约 15 秒三段审核：0–4 秒开头、4–10 秒正文配音/字幕、10–15 秒带旁白的结尾 CTA。
- 真实样片 WAV 在正文前写入 4 秒 PCM 静音，并把全部字幕 cue 同步后移；开头窗口不会提前播出正文旁白或字幕。样片正文单独压缩为一个自然短语，避免长首句挤掉 CTA，完整成片文案不受影响。
- 修复 ASS 字幕路径中英文撇号的 FFmpeg 多层转义，`Billionaire's Bride` 一类标题可正常渲染。
- 任务胶片带新增“当前任务 / 已归档”；终态任务可单条或批量归档，并可随时恢复。
- 归档只收起任务卡，不删除样片、成片、旁白、字幕、Manifest、错误日志、生产记录或磁盘文件。
- 右侧安全区预览新增“开头 / 正文字幕 / 结尾”三态；选择模板、简介卡、字幕、动画、口令卡或结尾卡时自动切换并实时刷新。
- 修复通用行内样式覆盖字幕预设的问题；柔和底板保持深色可读文字，电影阴影、极简、戏剧、阅读聚焦与逐词弹出均有清晰差异。
- 修复顶部 `SearchCard` 被其他 ASS 事件覆盖的问题：搜索口令事件固定使用 Layer 7；同时去除 `word_pop_sync` 可见文本末尾多出的右花括号。
- 制作台正文字幕的 `soft_pop` 使用专用关键帧并在动画每个阶段保留 `translateX(-50%)`，播放时不再右偏或越出安全区。
- 软件启动时会把**本机设备 ID** 名下、但已没有内存任务对应的陈旧队列租约释放，并把未完成记录标为 `interrupted`；不会抢占其他电脑的有效租约。

## 2. 15 秒结构化样片合同

样片不再简单截取成片前 15 秒。`PipelineRunner` 会生成完整审核时间线：

| 时间 | 审核内容 | 必看项 |
| --- | --- | --- |
| 0–4 秒 | 短钩子卡，可带平台/口令视觉信息；无正文旁白和正文字幕 | 开头吸引力、平台/口令、简介卡样式 |
| 4–10 秒 | 所选正文的真实 TTS、字幕、音乐和画面 | 女声音色/语速、断句、字幕预设和动画 |
| 10–15 秒 | 结尾卡与真实旁白 CTA | 悬念、下载引导、口令与结尾样式 |

`preview-manifest.json` 新增/冻结：

```json
{
  "duration_seconds": 15,
  "review_timeline": {
    "structured": true,
    "opening_card": {"start_seconds": 0, "end_seconds": 4},
    "story_body": {"start_seconds": 4, "end_seconds": 10, "narration_and_captions": true},
    "ending_card": {"start_seconds": 10, "end_seconds": 15, "narrated_cta": "..."}
  }
}
```

样片音画同步不是依赖播放器延迟：`assemble_narration_wav(..., initial_silence_seconds=4)` 会把静音直接写进 WAV，并给正文及 CTA 的每个 `SubtitleCue.start/end` 加上同样偏移。因此任何播放器、转码器或嫁接前端都能得到一致的 0–4 / 4–10 / 10–15 时间线。

为保证固定 15 秒内完整验收结尾，样片专用 `_preview_units()` 只从首个可朗读正文/钩子单元提取一个自然、完整的短语，并按正文窗口与 WPM 限制词数；它不会截断单词，也不会改写缓存的 `TextResult.polished_text`。全量成片继续使用完整润色正文和原始分集方案，不能把这个样片压缩规则复用于成片。

Settings Schema 12 把旧默认 `preview_seconds=30` 和过短旧值迁移为 15；制作台重新打开历史草稿时，也把旧内置 30 秒值规范化为 15 秒。30 秒此前不是制作台可选项，因此该转换不会覆盖用户从制作台明确选择的时长；其他合法自定义值继续保留。新下限为 12 秒，确保三段都有可审核窗口。

## 3. FFmpeg 路径修复

ASS 文件名位于 `filter_complex` 内，不是普通进程参数。旧代码把单引号写成 `\'`，经过 FFmpeg 两层解析后会提前结束引号，并把后续音频滤镜误当成 ASS 参数。

`storyforge.services.media.escape_filter_path()` 现在对单引号使用关闭引号、三反斜杠转义、重新打开引号的序列，并继续转义 Windows 盘符冒号。回归测试覆盖包含空格、盘符和 `Billionaire's Bride` 的真实失败路径。

同一轮字幕修复还冻结了两个 ASS 合同：`SearchCard` 对话事件使用 Layer 7，确保全程口令不被正文或卡片盖住；逐词弹出文本的 override tag 必须成对闭合，不能把结构用的 `}` 泄漏成画面中的可见字符。嫁接到其他渲染器时应保留这两个回归用例。

## 4. 可恢复任务归档

新增桌面/网页业务方法：

- `get_archived_jobs()`
- `archive_job(job_id)`
- `restore_job(job_id)`
- `archive_finished_jobs()`

仅 `completed / failed / cancelled / interrupted` 可归档；排队、制作中和待确认任务会被拒绝。员工只能处理自己的任务，管理员沿用全队权限。恢复只是重建胶片卡，不会重新渲染。

Catalog Schema 9 在 `production_records` 增加：

- `archived`
- `archived_at`
- `archived_by_user_id`
- `archive_snapshot_json`

完整 `RenderJob` 快照与生产记录一起持久化，因此关闭或重启 Hub 后仍可恢复。Schema 8 数据库会先补列、再创建归档索引，旧资料无需人工转换。

桥接返回合同：

```json
{
  "jobs": [{"id": "job-1", "archived": false}],
  "archived_jobs": [{
    "id": "job-2",
    "production_record_id": "record-2",
    "status": "failed",
    "archived": true,
    "archived_at": "2026-07-25T10:00:00+00:00",
    "archived_by_user_id": "user-1",
    "record_status": "failed"
  }]
}
```

`archive_job()` 与 `restore_job()` 返回 `job / current_jobs / archived_jobs`；归档响应中的 `job.archived` 为 `true`，恢复响应为 `false`。`archive_finished_jobs()` 另返回 `archived_count / archived_job_ids`。员工通过 `jobs.retry_own` 只能操作自己创建的生产记录，管理员沿用 `jobs.retry_all / drafts.manage_all / hub.manage` 的全队范围。旧 `clear_finished_jobs()` 仅为兼容保留，新界面和新嫁接项目应使用可恢复归档。

## 5. 前端预览合同

制作台右侧预览由 `state.productionPreviewScene` 控制三态。以下本批字段应立即反映：

- `video_template`
- `intro_card_preset` 与 `intro_card`
- `subtitle_preset`、`subtitle_animation` 与 `subtitle`
- `code_card_preset` 与 `code_card`
- `outro_card_preset` 与 `outro_card`

选择开头相关控件自动切到开头，字幕/动画切到正文，结尾卡切到结尾。预览只用于快速判断样式与安全区；最终成片仍以 FFmpeg/ASS 渲染结果为准。

| 右侧场景 | 必须即时反映的选择 |
| --- | --- |
| 开头 | `video_template`、全部简介卡预设/字段、平台 Logo/品牌色、口令卡预设/字段 |
| 正文字幕 | 全部字幕预设/字段、`none / fade / soft_pop`、`word_pop_sync` 三态颜色与弹出强度、口令卡 |
| 结尾 | 全部结尾卡预设/字段、精确平台/口令、CTA 和封面收尾布局 |

预览是同一个冻结 `production_settings` 的三个视图，不维护第二套样式默认值。其他项目嫁接时应让控件修改 DTO 后立即重绘相应场景，并允许用户手动切换三态复核全部设置。

制作台预览中的正文字幕以 `left: 50%` 和 `translateX(-50%)` 居中。`soft_pop` 必须使用专用 `production-subtitle-soft-pop` 关键帧，在起始和结束状态都保留 `translateX(-50%)`，再叠加 `translateY/scale`；不能复用会整体覆盖 `transform` 的通用弹出关键帧，否则动画开始后会向右偏移并可能越过安全区。

浏览器静态资源查询版本为 `v21`，Hub 升级后普通浏览器刷新即可取得新 UI。

## 6. 启动恢复与租约

`StoryForgeApi` 启动时会核对当前 `device_name` 的持久生产记录与本机内存队列。对已经消失的本机未完成任务：

- 将 `queued / preflight / sample_ready / awaiting_approval / running` 记录标为 `interrupted`；
- 清空本机持有的 `lease_owner_device / lease_expires_at / heartbeat_at`；
- 清理由该任务产生的草稿 `queue_claim` / lease gate；
- 保留生产记录、错误信息、日志和既有产物；
- 不释放设备 ID 不同的其他 Worker 租约。

这项处理避免重启后的幽灵任务继续占用约三分钟租约。它不是断点续渲染；需要用户恢复归档卡或对中断任务执行重试。

## 7. 兼容性与嫁接建议

- 公开业务模型仍建议通过版本化适配 API 嫁接，不要让外部程序直接写 SQLite。
- 归档应映射为“隐藏/恢复终态任务”，不要映射成删除。
- 嫁接方应保存 `review_timeline`，让审批 UI 可按三段跳转或生成缩略图。
- 外部渲染器若自己拼接 FFmpeg filter graph，必须沿用媒体服务的过滤器路径转义规则。
- 网页仍由 Hub 主机执行 TTS、FFmpeg、文件访问和队列；普通浏览器不是独立 Worker。
- 0.3.1 不包含 TikTok 登录、上传、自动发布或合规检查。

- `tests.test_ui_contract`：30/30 通过。
- `node --check ui/app.js`：通过。
- 本地构建依赖 `pip check`：通过。

本轮专项回归覆盖：15 秒三段时间线与旧 30 秒设置/草稿迁移、WAV 前置 4 秒静音与字幕 cue 同步偏移、样片正文自然短语压缩且完整成片文本不变、制作台 `soft_pop` 始终保留水平居中、含空格/盘符/英文撇号的 ASS 路径、`SearchCard` Layer 7、逐词弹出无可见右花括号、Schema 9 归档持久化与恢复、权限过滤，以及重启后只释放本机陈旧租约和草稿 `queue_claim`。
