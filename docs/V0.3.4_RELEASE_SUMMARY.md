# StoryForge Studio 0.3.4 发布与交接摘要

> 基准日期：2026-07-28  
> 源码版本：`0.3.4`  
> Catalog Schema：11  
> Settings Schema：17  
> Hub Protocol：1  
> Manifest Schema：2

本摘要说明 v0.3.4 的最终运行架构与新增合同。最终 Windows 构建目录、完整安装 ZIP、Hub 更新 ZIP、源码交接包、文件大小和 SHA-256 尚待正式构建验收，不能复用或改名旧版本产物冒充本版交付物。

## 本版结论

网页端和桌面端现在提供同一套业务功能，但不会突破浏览器的本机安全边界：

| 运行端 | 保存与执行内容 |
| --- | --- |
| Hub 主机 | 小说库、正文版本、封面、平台与口令、成员、共享大模型、团队生产预设、草稿、记录、审计和 3 日备份 |
| 员工制作电脑 | 本机视频、音乐、TTS/Kokoro/Edge/云语音调用、FFmpeg/GPU、语音缓存、临时文件、完整 MP4、可选纯旁白 WAV |
| 浏览器 | 显示同一制作台并发起业务操作；媒体方法通过 loopback 调用当前电脑的本机制作服务，不直接读取磁盘或运行 FFmpeg |

管理员不需要为员工指定素材、音乐或输出文件夹。员工只在自己的电脑选择目录，成片只保存在实际生成它的电脑；Hub 记录状态和受控引用，不承担全部媒体压力。

## 网页完整制作与后台服务

每台制作电脑只需完成一次初始化：

1. 安装同版本的完整 StoryForge 发布目录。
2. 打开一次 StoryForge，用 Hub 地址、员工账号、8 位密码和电脑名称完成设备绑定。
3. 双击 `enable_storyforge_worker.cmd`（界面名称“启用本机制作服务”）。
4. 回到浏览器刷新 Hub 页面，确认顶部显示当前电脑，并能读取本机 FFmpeg 和 TTS 状态。

脚本注册当前 Windows 用户、有限权限、登录触发的 `StoryForge Local Worker` 计划任务。它运行 `StoryForge Studio.exe --local-worker`，只监听 `127.0.0.1:18765–18770`；完整 StoryForge 窗口可以关闭。撤销时运行 `disable_storyforge_worker.cmd`。

Hub 主机的团队网页是另一项后台服务，默认端口 `8765`。当前验收环境地址为 `http://10.0.0.225:8765/`；局域网 IP 改变后，应使用 Hub 设置页显示的新地址。Hub 可无窗口运行，但不能代替员工电脑的本机制作服务。

Local Worker 连接响应会返回脱敏后的版本、FFmpeg、可用 H.264 编码器、推荐编码器和 TTS/Kokoro 就绪状态。API Key、命令、模型路径和可执行文件路径不会返回浏览器。网页必须显示当前员工电脑的状态，不得显示 Hub 主机状态冒充本机能力。

## Kokoro 轻量版与完整版

| 版本 | 内置 FFmpeg | 进程内 Kokoro/PyTorch | 可用配音方式 |
| --- | --- | --- | --- |
| 轻量版 | 是 | 否 | Edge TTS、Deepgram、外部 Kokoro HTTP |
| 本地 AI 完整版（`-WithLocalAI`） | 是 | 是 | 内置 Kokoro，并继续支持 Edge/Deepgram/HTTP |

轻量版页面显示“Kokoro 还未配置”是正确的能力提示，不代表网页或 FFmpeg 出错。若要地址留空直接使用 Kokoro，必须安装本地 AI 完整版，并在发布目录中保留完整 `local-ai\kokoro` 模型、配置和 Voice 文件。Hub 主机装有 Kokoro 也不会让员工轻量版自动获得本地 Kokoro；配音仍在员工电脑执行。

## 新增生产选项

### 可选封面结尾

- 字段：`production_settings.cover_outro_enabled`，默认 `true`。
- 生产预设、草稿、冻结 Job 和即时预览均保存该值。
- 开启：小说真实封面按所选动画铺满结尾画面。
- 关闭：不插入封面或封面动画，保持正文画面收尾。
- 两种模式都继续播放结尾 CTA 旁白、当前字幕样式、背景音乐和顶部搜索口令；都不恢复旧白色平台结尾卡。
- 旧草稿没有字段时按 `true` 迁移，保持升级前视觉结果。

### 可选纯旁白 WAV

- 字段：`production_settings.export_narration_audio` / `BatchSpec.export_narration_audio`，默认 `false`。
- 开启后，MP4 渲染及快速质检通过，再把已经生成的旁白轨原子复制为 `<成片文件名>_narration.wav`。
- WAV 不含背景音乐或素材原声，不会第二次调用 TTS，也不会改变字幕时间轴。
- 路径进入 `RenderJob.narration_audio_file`、Manifest、生产记录元数据和 `narration` Artifact。
- 导出失败会留下 `narration-export-error.log` 并把当前 Job 标为失败；不会登记半文件为成功，其他队列任务继续。
- `settings.hub.share_narration` 默认 `false`。默认只在员工电脑保存 WAV，Hub 只记元数据/本机受控引用；3 日 Hub 备份不包含该 WAV。

### 通用素材回退与批次卷宗

- 视频首先匹配员工本批所选素材总目录中的题材子目录。分类不存在或没有可用视频时，从同一总目录随机选取有效视频作为通用回退；不得访问 Hub 或其他员工电脑的素材。
- 回退必须在任务警告、Manifest 和生产记录中明确标注，但不得修改小说 `story_mood`、人工题材选择或把通用素材显示成题材命中。员工所选总目录也没有有效视频时才让该任务失败并继续下一任务。
- 制作台任务胶片带按稳定 `batch_id` 聚合成默认折叠的“批次卷宗”。卷宗摘要显示总体状态、总进度和成功/失败数量；展开后显示单视频进度、错误与操作，并可跳转生产记录。
- 批次卷宗只是 UI 投影，不合并底层 Job/ProductionRecord/Attempt，不改变服务端分页、权限、归档恢复和失败重试合同。
- 点击“直接生成完整视频”后，已提交批次立即冻结为独立卷宗并在后台继续；制作台同时切换为下一批新草稿，不要求等待上一批结束。新草稿保留小说、女声、样式和本机目录，清空口令、发布账号、分集和批次临时文案，避免误复用。
- 同一制作电脑可连续提交任意数量批次。调度器按提交顺序严格 FIFO 完整耗尽一批后再运行下一批；单条或整批失败会记录原因，但不会阻塞后续批次。批次总数和总体进度来自 Catalog 持久化摘要，不受 UI 分页或流式加载窗口影响。
- 上述功能已纳入 v0.3.4 源码回归与真实浏览器连续批次验收；Windows 最终构建仍须在生成交付包后另做安装冒烟。

## 兼容与迁移

- Catalog Schema 保持 11。
- Settings Schema 升至 17：Schema 15 增加纯旁白导出默认关闭；Schema 16 增加封面结尾默认开启；Schema 17 增加 Hub 旁白共享默认关闭。
- 旧 `preview` Job、批准状态和 `.previews` 文件仍只用于历史解码和迁移。新制作继续直接创建 `job_kind="full"`、`status="queued"`、`preview_required=false` 的完整任务。
- 生产预设可保存两个新增布尔字段；套用预设后仍不覆盖小说、平台、口令、分集、发布账号、已选 Voice ID 或员工本机目录。
- 更新安装后应重启 Hub 服务和每台制作电脑的 Local Worker，避免旧进程继续报告旧版本能力。

## 最短验收清单

1. 浏览器打开 Hub 地址并登录员工账号。
2. 完整 StoryForge 窗口关闭时，页面仍显示已连接本机制作服务。
3. FFmpeg 和实际可用 H.264 编码器来自当前员工电脑。
4. 完整版 Kokoro可生成试听；轻量版明确提示改用 Edge/Deepgram/HTTP，不给出假就绪状态。
5. 选择员工电脑自己的视频、音乐和输出目录，管理员端无需配置路径。
6. 关闭/开启封面结尾时，即时预览同步变化，最终成片的 CTA 与字幕均继续。
7. 开启纯旁白后同时得到 MP4 和 `_narration.wav`；WAV 无 BGM/素材原声，且默认不上传 Hub。
8. 单个任务失败不阻塞同批其他任务，Hub 生产记录能看到当前电脑、状态和错误。
9. 删除或留空某个题材子目录后，任务使用员工素材总目录中的可用视频，并在任务/Manifest/记录显示通用回退而不改变题材；总目录无视频时才失败。
10. 同一批创建多条视频时，胶片带先显示一个批次卷宗；展开能看到每条视频并跳转到对应生产记录。
11. 第一批仍在制作时立即建立并提交第二批；两批分别显示，第二批为“等待制作”，第一批完成或失败后才按 FIFO 启动第二批。

## 故障定位

- **Hub 地址拒绝连接**：检查 Hub 主机的 `StoryForge Hub` 任务、TCP 8765 和专用网络防火墙。
- **网页能打开但不能试听/生成**：当前员工电脑运行一次 `enable_storyforge_worker.cmd`，在任务计划程序确认 `StoryForge Local Worker` 正在运行，再刷新页面。
- **网页显示缺少 FFmpeg**：先确认页面连接的是当前电脑；再运行发布目录中的 `diagnose_storyforge.cmd`。浏览器本身不需要也不能安装 FFmpeg。
- **Kokoro 还未配置**：若为轻量版，改用 Edge/Deepgram/Kokoro HTTP 或换本地 AI 完整版；若为完整版，核对 `local-ai\kokoro` 和对应 Voice 文件。
- **仍显示旧版能力**：同时重启 Hub 后台服务和员工电脑 Local Worker，并在浏览器执行强制刷新；只刷新页面不能替换仍在运行的旧 EXE 进程。
