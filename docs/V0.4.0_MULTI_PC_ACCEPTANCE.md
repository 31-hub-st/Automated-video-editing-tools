# StoryForge Studio 0.4.0 多电脑生产验收门槛

> 本文是 0.4.0 的发布门槛，不是功能愿望清单。任一“必须”项未通过，都不能向团队宣布该版本已经可以稳定多机生产。

## 1. 已锁定的产品合同

- Hub 主机只保存小说、平台、口令、账号、团队方案、AI 服务与生产记录。
- 每台制作电脑使用自己的视频、音乐、TTS、FFmpeg/GPU、缓存和输出目录；完整 MP4、纯旁白 MP3、历史预览、内部 WAV、ASS 和字幕对齐文件始终不上传 Hub。Hub 只登记业务记录、文件元数据、校验信息和本机受控引用，管理员没有可开启的生产媒体上传开关，也不能从其他电脑远程播放或下载员工本地成片。
- 制作电脑可以通过桌面窗口或 Hub 网页使用同一套功能。Hub 网页的媒体操作必须由当前电脑的 Local Worker 执行。
- 选择任意一个或多个分集/子段时，所选正文按顺序合并成一条连续视频的内容单元。选择从第 1 集开始时不生成上集回顾；从后续集开始时只在整组开头生成一次回顾；合并后预计超过 10 分钟只提醒，不拆成多条视频。
- 默认 `output_mode=video_and_mp3`，交付一份完整 MP4 和一份同基名 48 kHz、192 kbps 纯旁白 MP3；显式 `audio_only` 提供“仅 MP3”模式，不存在 video-only。发布目录不得混入日志、字幕、中间 WAV、JSON 或临时文件。
- Settings Schema 18 把旧 `export_narration_audio=true`、`false` 或缺失都安全迁移为 `video_and_mp3`；只有显式 `output_mode=audio_only` 才只输出音频。
- AI 服务繁忙或失败时允许排队和重试，但不得静默降级为低质量本地规则。最终失败的任务要跳过并继续后续任务。
- 当前素材基本为 60 FPS，因此完整视频默认输出 60 FPS；低配置电脑仍可按批次改为 30 FPS。这里不做 AI 插帧，低帧率源素材只按输出时间轴重复帧。

## 2. 单台制作电脑必须通过

1. 使用员工账号登录；新员工默认密码为 `xs123456`。首次登录后建议修改，但不强制，也不作为本次验收门槛。
2. Local Worker 自动启动并能重新连接 Hub；完整桌面窗口关闭后仍可使用。
3. Worker 与网页必须都是本版协议 2；旧协议不兼容时明确要求升级，不能继续提交任务。
4. 自检能确认 FFmpeg、H.264 编码器、所选 TTS、视频目录、音乐目录、输出目录、可用磁盘空间和 Hub 连通性。
5. 能读取 Hub 小说库、平台口令和团队预设，但所有素材与成片路径均来自当前电脑。
6. 能试听候选女声。
7. 能提交两个连续批次；第一批运行时可以继续配置并提交第二批。
8. 完成任务后，发布目录只包含同基名 `.mp4` 与 `.mp3`；“仅 MP3”任务只包含 `.mp3`。
9. Hub 能看到成员、电脑、小说、批次、进度、成功或失败原因、产物元数据和校验，但不能读取、播放、下载或改写员工本地成片。

## 3. 多电脑必须通过

- 一台真实 Hub 主机和当前全部真实制作电脑同时在线并显示正确、不同的设备身份；Hub 主机本轮不自动领取渲染任务。
- 当前全部制作电脑同时试听、请求 AI 和提交不同批次，不发生串号、串路径或串素材。
- 同一任务只允许一台电脑持有有效租约；短暂掉线恢复后不能被两台电脑重复制作。
- Hub 短暂不可达时任务显示“正在重连”，恢复后队列继续；不得静默停止。
- 软件或 Worker 重启后，尚未开始且带完整快照的持久化任务自动按原批次顺序恢复；上次正在执行的任务明确标记中断并可从生产记录重试。
- 取消任务或安全退出时，任务级取消令牌必须终止该任务的 FFmpeg/TTS/探测/质检进程树，等待 Worker 停止后再写中断状态；取消后迟到回调不得恢复进度或发布成片。
- 一台电脑失败不阻塞其他电脑和同机后续任务。

## 4. 真实成片质量抽检

每台电脑至少生成一条 3–10 分钟真实视频，并检查：

- 开头、正文中段和封面结尾均可正常解码，无黑屏、花屏或截断。
- 旁白完整、无异常长静音，背景音乐不遮盖人声。
- 字幕与旁白对应，文字居中且不越出安全区。
- 口令、平台名、封面与所选小说一致。
- MP3 可独立播放，采样率 48 kHz、目标码率 192 kbps，内容与该视频旁白一致且不含 BGM/素材原声。
- 文件名足以识别小说、平台、口令、批次和序号。
