# StoryForge Studio 0.4.3 单目录便携稳定版交付说明

交付基线日期：2026-07-31

## 发布结论

0.4.3 将员工制作端统一为单目录便携版本。推荐安装根目录为 `D:\StoryForge`，程序文件位于根目录，所有可变运行数据位于 `D:\StoryForge\StoryForgeData`。员工仍可把视频素材、音乐和最终成片放在自己选择的其他本地目录。

## 最终交付物

最终金版使用全新 PyInstaller 工作目录无缓存构建；完整安装包与 Hub 更新包来自同一份已验收快照，内容和 SHA-256 完全一致。

生产构建必须显式指定纯英文/ASCII 的输出目录与工作目录：

```powershell
& '.\scripts\build_exe.ps1' `
  -WithLocalAI `
  -OutputDirectory 'D:\StoryForgeBuildTemp\dist' `
  -WorkDirectory 'D:\StoryForgeBuildTemp\work' `
  -HubEndpoint 'http://10.0.0.225:8765'
```

省略目录参数只用于临时构建；源码路径含中文时，脚本会自动使用源码所在盘根目录下的 `StoryForgeBuildTemp\dist` 和 `StoryForgeBuildTemp\work`，避免默认命令落入中文 PyInstaller 工作路径。

## 安装目录合同

- 使用纯英文/ASCII、本地固定磁盘、当前 Windows 用户可写的短路径，推荐 `D:\StoryForge`。
- 禁止安装到中文/Unicode 路径、`Program Files`、OneDrive/网盘同步目录、网络共享和可移动磁盘。
- 必须分发完整目录，不能只发送 `StoryForge Studio.exe`，也不能在 ZIP 内直接运行。
- 首次启动前发布包内不得存在 `StoryForgeData`；该目录只能由目标员工电脑创建。
- 更新包不得包含、覆盖或删除 `StoryForgeData`。

## 本版稳定性边界

- 硬件编码器在启动时串行短探测 NVENC、QSV、AMF，首个可用项成功后立即停止；始终保留 `libx264` CPU 兜底，避免并行探测抢占显卡与内存。
- 内置 Kokoro 默认使用 CPU，并限制 PyTorch 线程，避免在 16 GB 员工机上与 FFmpeg 同时争抢显存和 CPU；高级部署仍可通过明确配置调整。
- 更新检查在本机有活跃渲染时延后下载、校验和解压，避免更新与生产争用磁盘、CPU 和内存。
- TTS 与试听缓存采用有上限、按访问时间清理的策略；崩溃任务只清理可重新生成的 WAV/临时媒体，保留 Manifest、命令和错误日志。
- 便携模式将设置、数据库、WebView、缓存、临时目录、日志、更新状态和渲染工作区统一放入 `StoryForgeData`，不会在其他盘根目录创建隐藏回退缓存。
- 员工安装根目录含非 ASCII 字符或不可写时，程序在创建运行数据前停止并明确提示移动整个文件夹。

## 0.4.2 → 0.4.3 发布禁令

由于 0.4.2 旧更新器不满足本次数据目录迁移的安全条件，**严禁把 0.4.3 作为自动更新推送给仍运行 0.4.2 的员工机**。

必须使用以下受控流程：

1. 停止 0.4.2 更新公告，等待员工机当前任务完成。
2. 完全退出员工机的旧桌面端和旧 Worker。
3. 将完整 0.4.3 包解压到新的 `D:\StoryForge`，不能覆盖式拼接旧目录。
4. 首次启动 0.4.3，使用原账号密码登录并等待迁移完成。
5. 检查设备上报 0.4.3、本机 FFmpeg/TTS 状态，并完成一条真实 MP4 + MP3 任务。
6. 首台灰度通过后再逐台部署；未验收电脑不得继续批量制作。

0.4.3 首次启动会从 `%APPDATA%\StoryForgeStudio` 和 `%LOCALAPPDATA%\StoryForgeStudio` 复制长期数据。目标文件已存在时不会被旧文件覆盖；SQLite 数据库通过一致性备份复制。旧 Worker 仍运行时迁移会延后并拒绝启动第二个队列。

迁移不会复制旧 `cache`、`render-work`、`runtime-temp`、`updates` 和旧 Worker 状态。成功复制后，只会清理旧目录中确定可重新生成的缓存、临时文件、旧更新下载和渲染媒体；旧设置、数据库、日志、命令、Manifest 与未知文件继续保留，供回滚和诊断。管理员应在 0.4.3 真实任务验收通过后再决定归档或删除旧 C 盘数据。

## 0.4.3 后续更新合同

- 只有已经运行 0.4.3 或更高版本的员工机才能进入新便携更新流程。
- 下载、校验、待安装状态和最多 3 日的回滚副本都位于 `StoryForgeData\updates`。
- 活跃渲染期间延后更新资源工作；安装只在进程安全退出后执行。
- 失败时恢复已覆盖的程序文件，不破坏 `StoryForgeData`。
- Hub 主机不能把“已发布”当作“员工机已安装”；必须以设备版本上报和真实任务冒烟为准。

## 日志与排障入口

| 类型 | 默认路径 |
|---|---|
| 启动与运行日志 | `D:\StoryForge\StoryForgeData\logs` |
| 单任务工作区 | `D:\StoryForge\StoryForgeData\render-work\<批次>\<任务>\` |
| 任务级错误 | 上述任务目录内的 `job-error.log` 或 `render-error.log` |
| 更新状态、缓存与回滚 | `D:\StoryForge\StoryForgeData\updates` |
| 旧数据迁移结果 | `D:\StoryForge\StoryForgeData\.legacy-appdata-migration-v1.json` |

排障时优先收集相应日志和迁移结果文件，不要复制整个素材库或成片目录。

## 发布前验收清单

- 版本号在源码、EXE 自检、更新清单和设备上报中均为 0.4.3。
- 完整 ZIP 不含 `StoryForgeData`，且包含 EXE、连接配置、FFmpeg、约定 TTS 组件及管理员诊断工具。
- 在纯英文可写路径完成冻结态启动；在中文路径和不可写路径能明确拒绝且不产生隐藏回退数据。
- 从准备好的 0.4.2 C 盘样本完成一次受控迁移，确认新数据不覆盖、旧长期数据仍可回滚。
- 在 16 GB 员工机验证单 Worker、候选配音、常规视频、仅配音、已有配音更换素材、队列继续和取消/失败后的资源释放。
- 用单素材和多素材各完成一条 1080×1920、60 FPS MP4，并生成同名纯旁白 MP3；确认界面可操作、进度持续更新且无黑屏/整机假死。
- 验证活跃渲染时更新下载延后，空闲重启后安装成功，`StoryForgeData` 内容保持不变。
- 对最终 ZIP 做全量 CRC/结构检查，再生成并发布最终 SHA-256 清单。

## 清理、卸载与回滚

- 正常卸载 0.4.3 员工便携版：先退出 StoryForge 与 Worker，再删除整个 `D:\StoryForge`。无需到 C 盘寻找 0.4.3 的活动数据。
- 员工另行选择的视频素材、音乐与最终输出目录不在安装目录内，不会随卸载删除。
- 从 0.4.2 迁移的电脑在验收前保留旧程序和旧 C 盘长期数据。需要回滚时先停止 0.4.3，再使用旧目录；绝不同时运行新旧 Worker。
- 验收完成后，管理员可归档或删除旧 `%APPDATA%\StoryForgeStudio` 与 `%LOCALAPPDATA%\StoryForgeStudio`。若仍需审计历史任务，应先保留其中的数据库、日志、命令和 Manifest。
