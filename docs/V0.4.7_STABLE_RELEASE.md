# StoryForge Studio 0.4.7 稳定版交付报告

发布日期：2026-08-02  
应用版本：`0.4.7`  
Catalog Schema：`14`  
Settings Schema：`19`  
Local Worker / 浏览器协议：`3 / 3`

## 1. 本版解决的问题

- Worker 增加空闲、渲染、冷却、暂停和故障状态，只允许一个重型媒体任务占用员工电脑，并在资源不足时安全停止而不是继续拖垮系统。
- 队列租约增加 `lease_generation` 栅栏；领取、重试、取消、迟到回调和流式进度均重新校验任务所有权，旧进程不能覆盖新任务结果。
- 生产流程记录阶段、耗时、资源峰值、编码器回退和任务关联 ID；管理员可生成脱敏诊断包定位员工电脑问题。
- 统一 RPC 注册表生成 Hub、网页、Worker 和桌面允许的方法与权限，降低某一端升级后漏接口造成的兼容故障。
- 更新包要求发布证明、SHA-256、原子替换与回滚；员工电脑只在空闲时安装，不热替换正在运行的程序。
- 统一存储分类和配额：小说源文件、最终成品和当前更新包受保护；渲染缓存、旧预览、过期日志和历史回滚可统计后清理。
- 保持既有业务合同：Hub 保存固定资料和记录，视频、音乐、TTS、FFmpeg/GPU、临时文件和最终成品留在员工电脑。

## 3. 自动验收结果

- Python 全量回归：`950` 项，`0` 失败，`2` 跳过。
- 冻结包启动、WebView、UI、Worker、内置 FFmpeg 与内置 Kokoro 检查通过。
- 311 秒、30 FPS、封面结尾开启的冻结 EXE 真实渲染通过：H.264、1080×1920、单音轨、965 条 ASS 字幕。
- 600 秒、60 FPS、封面结尾关闭的冻结 EXE 真实渲染通过：H.264、1080×1920、单音轨、965 条 ASS 字幕。
- 最终发布目录证明与独立包体冒烟通过。稳定验收报告先绑定冻结 EXE；发布证明和包体冒烟随后验证最终目录，因此以前者中的预发布 attestation 字段为准判断最终签发并不正确。

这些结果证明正式包在构建机上的冻结运行与长渲染。每台员工电脑的显卡驱动、本机素材、目录权限和磁盘状态仍需在更新后完成一次真实任务冒烟；设备上报才是员工硬件验收结论。

## 6. 嫁接边界

二次集成应保留以下边界：

1. Hub 负责账号、小说、平台口令、大模型、方案、队列元数据和记录。
2. 员工 Worker 负责本机 TTS、视频、音乐、字幕、FFmpeg/GPU、缓存和成品。
3. 所有跨端 RPC 通过 `storyforge/rpc_contract.py` 的统一契约登记，不单独维护另一份白名单。
4. 队列更新必须携带租约代次，不绕过取消、迟到回调和原子发布检查。
5. 更新必须验证发布证明与 SHA-256，并在空闲安全点安装。

完整实体、接口和迁移说明见 [整体项目嫁接报告](STORYFORGE_INTEGRATION_REPORT.md)。
