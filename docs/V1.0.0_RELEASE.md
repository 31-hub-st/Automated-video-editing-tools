## 2. 用户可见交付

- 一页制作台与即时预览；提交批次后可立即继续配置下一批。
- 三种制作方式：常规视频生成、仅生成配音、已有配音更换素材。
- 管理员与员工两级权限；员工只使用账号和 8 位密码接入。
- Hub 保存共享小说、平台、口令、成员、预设和生产记录；员工电脑使用自己的素材、TTS、FFmpeg、缓存和输出目录。
- 按批次卷宗查看、归档、恢复和重试任务。
- 核心完整包更新、独立语言组件更新、回滚和窄边界 Hub 备份。

详细业务合同见 [制作流程最终基线](PRODUCTION_WORKFLOW_FINAL_BASELINE.md)，技术接手说明见 [项目接手与功能嫁接说明](STORYFORGE_INTEGRATION_REPORT.md)。

## 3. 输出合同

| 制作方式 | 接口值 | 员工发布目录产物 |
| --- | --- | --- |
| 常规视频生成 | `video_and_mp3` | 仅完整 MP4 |
| 仅生成配音 | `audio_only` | 仅一份 48 kHz、192 kbps MP3 |
| 已有配音更换素材 | `reuse_audio` | 仅新的完整 MP4 |

视频默认 H.264、1080×1920、60 FPS。ASS、内部 WAV、命令、Manifest、恢复文件与日志只进入 `<StoryForgeData>\render-work`，不得混入员工发布目录。

## 4. 兼容与迁移

- `video_and_mp3` 是兼容旧接口保留的枚举名，不能按名称推断额外 MP3。
- 旧 `export_narration_audio` 字段由 Settings Schema 20 迁移；新任务遵守当前输出合同。
- 从任意 `0.x` 旧版迁移时，必须结束旧任务并完全退出旧 Worker，把 `v1.0.0` 完整包安装到新的纯英文可写目录；真机任务通过后再清理旧目录。
- `StoryForgeData` 是受保护的用户数据目录，不得打进核心程序包，也不得被更新器覆盖。

## 7. 发布与下发策略

1. 先升级并验证 Hub 主机，确认小说库、网页登录、备份和生产记录正常。
2. 本次 `v1.0.0` 完成打包与 GitHub 保存后，**不自动发布给员工电脑**。
3. 管理员先在非生产时段用一台员工真机完成登录、试听、三种模式最小任务、归档、重启和回滚冒烟。
4. 验收通过后，再由管理员决定人工分发完整 ZIP，或在 Hub 主动发布更新清单。
5. 核心更新只在队列空闲和安全重启点安装；渲染中不得热替换。

## 8. 回滚

- 更新器保留上一版核心程序回滚副本，最多保留 3 日。
- 安装失败时先退出 StoryForge 与 Worker，使用已验证的上一版完整目录恢复程序文件，保留原 `StoryForgeData`。
- Hub 数据恢复使用 `<StoryForgeData>\hub-backups` 中经过校验的 `.sfbak`；恢复前系统必须创建安全快照。
- 不得用复制中的 SQLite、员工输出目录或渲染缓存替代 Hub 备份。

## 9. 已知边界

- 当前为 Windows-first 产品；冻结包依赖 WebView2 与随包 FFmpeg。
- 每台制作电脑同一时间只运行一个重型媒体任务，以稳定性优先。
- Hub 网页不能直接读取另一台电脑的素材或成片；媒体调用必须由当前员工电脑的本机制作服务执行。
- 局域网默认使用 HTTP；跨地点应使用可信 VPN/HTTPS 网关，不能直接把 8765 暴露到公网。
- 不同 TTS 供应商和语种的可用 Voice 不完全一致；只展示真实可用候选。
- 即时预览是布局近似，不是逐帧渲染样片。
