# StoryForge 网页端使用说明

> 适用源码版本：StoryForge Studio `v1.0.6`。桌面窗口、Hub 团队网页和制作电脑本地网页使用同一套账号、页面与制作流程。浏览器不能直接运行 EXE 或读取任意本地磁盘，因此媒体操作由访问网页的当前员工电脑上的 Local Worker（界面名称“本机制作服务”）执行；完整 StoryForge 窗口无需一直打开。

StoryForge 网页端与桌面制作端共用小说库、平台口令、成员权限、团队生产预设、制作草稿和生产记录。Hub 主机提供小说库、平台口令、账号、大模型、预设和记录；每台制作电脑使用自己的 TTS、素材盘、音乐、字幕处理、队列、FFmpeg/GPU、临时文件和输出目录。因此员工可以全程在浏览器界面操作，同时不会把媒体生产压力集中到 Hub，也不需要管理员替员工指定文件夹。

## 最快开始

1. 在长期运行的主电脑打开 StoryForge，进入“设置 → 多电脑协同”，选择“设为 Hub 主电脑”。
2. 保持端口为 `8765`，保存后重启 StoryForge；需要长期运行时，运行发布目录提供的 Hub 后台服务入口（源码脚本为 `scripts\enable_storyforge_hub.ps1 -DataRoot <正式固定数据目录>`）。
3. 管理员在“设置 → 成员账号”建立管理员或员工账号。新员工默认密码为 `xs123456`；首次登录后建议修改，但当前版本不强制，也不影响接入验收。
4. 其他制作电脑复制管理员提供的完整 StoryForge 发布文件夹并双击 EXE；发布包已预置 Hub 地址。首次启动时由员工选择本机 `StoryForgeData` 数据目录，后续设置、缓存、日志、组件和任务工作区均使用该目录。
5. 员工只输入账号和密码。软件自动读取 Windows 电脑名称、登记设备、安全保存内部设备凭据，并注册只监听本机的制作服务；不显示令牌，也不要求运行脚本。
6. 登录成功后，可关闭完整桌面窗口，再在该制作电脑的浏览器打开 Hub 地址，例如：

   `http://10.0.0.225:8765/`

7. 页面顶部显示“网页控制台 · 当前电脑名称 · 本机生成”，且运行环境中的 FFmpeg/TTS 状态来自当前电脑后，即可直接试听、选择本机目录并批量生成。也可打开本机服务地址（通常为 `http://127.0.0.1:18765/`，端口占用时依次使用 `18766–18770`）。

Hub 后台服务和员工电脑的本机制作服务是两件事。Hub 服务维持 `8765` 团队网页；本机制作服务维持当前员工电脑的 TTS、目录与渲染能力。两者都可作为当前 Windows 用户的登录任务运行，不要求完整桌面窗口常开。若 Hub 页面显示“连接被拒绝”，先在主电脑确认 `StoryForge Hub` 正在运行，再检查 Windows 防火墙是否允许专用网络访问 TCP 8765；若页面能打开但不能试听或生成，则检查员工电脑的 `StoryForge Local Worker` 登录任务。

## 网页端可以做什么

- 登录并按账号权限查看共享小说库、平台、口令、发布账号、草稿和生产记录。
- 管理员维护小说、简介、封面、平台、Logo、口令、发布账号、成员、设备和软件更新。
- 员工选择小说与分集，准备并保存自己的制作草稿，配置字幕、简介卡/口令卡开关和时间轴位置、封面结尾、音乐和其他本批参数。
- 员工可在制作台编辑本批的平台口令卡文案和结尾引导文案；默认值来自平台模板与当前口令。这些覆盖只写入员工自己的本批草稿，不修改团队平台模板，不需要也不授予 `platforms.manage`。
- 员工保留“设置”入口，可保存按账号与当前电脑隔离的个人制作默认值，检查本机 FFmpeg、H.264 编码器、Kokoro/Edge TTS，并更新当前客户端；团队、Hub、账号、密钥和长期资料配置不会在员工设置中显示。
- 生产方案只显示“团队默认 / 我的方案”。团队默认由管理员在设置中维护，只影响之后新建的批次；员工可覆盖本批参数，并且只能编辑或删除自己的个人方案；管理员可查看和删除全部成员方案。旧版内置、团队共享和无所有者方案不再显示。
- 在制作台查看开头、正文字幕和封面结尾三态 HTML/CSS 即时预览；修改预设后右侧画面即时刷新。
- 可关闭“使用小说封面结尾”；关闭后保留正文画面收尾，CTA 旁白和字幕继续，不绘制封面及其动画。
- 三种制作方式分别交付：常规视频生成只交付最终 MP4；仅生成配音只交付 MP3；已有配音更换素材只交付新的 MP4。兼容接口值 `video_and_mp3` 仍代表常规视频生成，但当前不再额外交付旁白 MP3。
- 上传 TXT/DOCX、故事简介、小说封面、平台 Logo；管理员还可上传完整桌面更新 ZIP。
- 在权限允许时调用小说语种与题材分类等共享 AI 能力。
- 查看进行中、已结束和已归档的任务，归档/恢复记录及产物元数据。只有网页所在的当前员工电脑已连接自己的 Local Worker，且文件仍在该电脑时，才能从该机打开本地成片；管理员在其他电脑只能看状态、校验和本机引用，不能经 Hub 播放或下载员工成片。
- 任务胶片带按 `batch_id` 折叠成“批次卷宗”，先展示批次总体状态、进度和数量；展开后查看单条视频、错误与操作，并可跳转到对应生产记录。归档按批次分页读取，任务很多时点击“加载更多”，不会一次加载全部历史。
- 视频素材不按小说题材匹配。系统只递归扫描员工本批选择的视频素材文件夹，并由员工决定使用哪一批素材；所选目录没有可解码视频时才报错。

即时预览只检查布局、字体、颜色、安全区、顶部口令卡和封面结尾，不生成 MP4、WAV、ASS 或生产记录，也不代表逐帧渲染效果。当前生产流程没有独立 preview 审批步骤。

正常地址使用真实后端，不会在连接失败时偷偷切到 Mock。只有开发人员显式打开 `?demo=1` 才进入无真实数据的界面演示。

## 网页、Hub 与本机制作服务的职责

以下操作需要访问制作电脑本机的模型、素材、目录、GPU/编码器或 FFmpeg。员工可以在 Hub 团队网页中点击这些操作，但调用会被转交给当前电脑的本机制作服务，而不是在 Hub 主机进程中执行：

- 生成和试听候选配音；
- 在 Kokoro 本地配音与 Edge TTS 免费多语种配音之间自行切换；
- 选择本机视频、音乐与输出目录；
- 直接创建完整视频队列；
- 启动、停止或取消本机队列；
- 重试失败的媒体任务；
- 执行 Kokoro、其他本地 TTS、字幕对齐和 FFmpeg 渲染；
- 直接创建完整视频任务、控制本机队列和重试本机失败任务。

Hub 服务端通过 `storyforge.web.WEB_DESKTOP_ONLY_MEDIA_METHODS` 拒绝在主机进程内直接执行媒体 RPC；当 Hub 页面运行在已经绑定并启用本机制作服务的员工电脑上时，前端只探测 `127.0.0.1:18765–18770`，向 Hub 领取短时设备票据，再把生产调用交给该电脑。制作电脑自己的 loopback 网页则直接调用同一台电脑的本地 API。网页和桌面的业务功能一致，运行位置仍严格隔离。

本机白名单覆盖完整生产所需的候选配音、免费 TTS 切换、目录选择、完整任务创建、队列启动/停止、任务查询、选中取消、重试、归档/恢复、分页读取归档以及打开本机输出目录；旧版 `approve_preview` / `regenerate_preview` 始终不开放。每次请求都会重新校验 Hub 账号、设备和有效权限，停用账号、停用设备、撤销设备凭据或账号级禁用权限后立即生效。

## 当前制作流程

1. 在制作电脑浏览器打开 Hub 网页，选择小说、平台、口令和一个或多个分集/子段，配置字幕、简介卡、封面结尾开关与动效等本批参数。所选内容按正文顺序合成一条连续视频；从第 1 集开始时无回顾，从后续集开始时只在整组开头回顾一次，合计超过 10 分钟只提醒、不拆条。
2. 保存草稿，并用三态即时预览检查开头、正文字幕和封面结尾。
3. 在同一页面生成并试听候选女声，选择当前电脑的视频、音乐和输出目录，并选择常规视频生成、仅生成配音或已有配音更换素材。
4. 点击生成。本机一次创建全部 `job_kind="full"`、`status="queued"` 任务，`preview_required=false`，随后按所选 `output_mode` 自动执行并冻结为独立批次卷宗。
5. 制作台立即进入下一批新草稿：保留小说、女声、样式和本机目录，清空口令、发布账号、分集及本批临时文案。无需等待上一批结束，可持续选择下一部小说或下一组分集并加入队列。
6. 同一电脑上的批次严格按提交顺序 FIFO 执行；单个任务或某批失败时保留原因并继续后续批次。网页端可按批次查看进度、结果和归档记录。

如果一台电脑只打开 Hub 地址、但从未打开完整 StoryForge 登录，它可以维护获准的资料并查看任务元数据，不能借用主机替它渲染，也不能查看其他员工电脑的本地成片。需要出片的电脑必须复制完整 StoryForge 并用账号密码登录一次；本机制作服务随后自动启用，不要求完整窗口常开。

## 两类账号

| 角色 | 默认工作范围 |
| --- | --- |
| 管理员 | 维护小说、平台、口令、发布账号、成员、设备、Hub 和更新；查看全队记录并处理管理事项。 |
| 员工 | 查看可用固定资料，建立和修改自己的制作草稿，在制作电脑本地网页执行配音、生成和自己的任务处理；可管理个人制作默认值与当前电脑运行环境，但不能管理小说、口令、成员或 Hub。 |

管理员可按账号额外开启或禁止业务权限。网页后端在每次请求重新读取有效权限，并校验草稿和记录所有权；前端隐藏按钮不是权限边界。管理员身份也不能让 Hub 团队网页操作另一台电脑的本地磁盘或渲染器。

## 浏览器文件与制作电脑文件

网页上传的小说、简介、封面、平台 Logo 和更新包先安全保存到 Hub 主电脑，作为共享资料使用。浏览器不能打开访问者电脑或主电脑的资源管理器，也不能任意浏览任何磁盘。

Hub 可能在主电脑选择的 `<StoryForgeData>` 下维护以下受控网页工作目录：

```text
<StoryForgeData>\web-workspace\videos
<StoryForgeData>\web-workspace\music
<StoryForgeData>\web-workspace\output
```

这些目录只用于 Hub 共享资料存储和旧数据兼容，不是团队媒体盘。视频素材、音乐目录和最终 MP4/MP3 都在实际执行任务的制作电脑配置；从另一台电脑保存的绝对路径不会被直接继承，本地大视频和渲染压力也不会转移到 Hub。员工发布目录按制作方式只平铺最终 MP4 或 MP3；Manifest、日志、ASS、内部 WAV、恢复日志和缓存位于该电脑 `<StoryForgeData>\render-work` 等数据目录，不进入发布文件夹。Hub 始终只保存生产记录、文件元数据、校验和员工电脑上的受控本机引用，永不上传完整 MP4、MP3、内部 WAV、ASS 或字幕对齐文件；管理员不能通过 Hub 远程播放或下载员工本地成片。

## 当前视频结尾与输出模式

- “使用小说封面结尾”默认开启。开启时最后 5–7 秒使用真实小说封面铺满 9:16 全屏，保持正确比例并根据预设使用淡入、轻推近、轻拉远、慢速平移或柔和视差。
- 关闭封面结尾后，不显示封面及封面动画；视频保持正文画面收尾，CTA 旁白、字幕和顶部搜索口令仍继续。
- 不再叠加白色平台结尾卡。
- 结尾 CTA 由旁白念出，并沿用当前普通字幕或逐词变色字幕样式同步显示。
- 顶部搜索口令卡默认保持到视频结束；员工可在本批草稿中关闭它，或设置开始时间与显示时长。口令、旁白、字幕和生产记录读取同一快照。
- `output_mode=video_and_mp3` 是为兼容既有接口保留的名称，当前“常规视频生成”每条任务只交付通过质量检查的完整 MP4。
- `output_mode=audio_only` 跳过视频渲染，只交付纯旁白 MP3。
- `output_mode=reuse_audio` 读取可靠的配音与字幕索引，使用本机新视频素材只交付新的 MP4。
- Settings Schema 20 会把旧 `export_narration_audio=true`、`false` 或缺失统一迁移为 `video_and_mp3`；迁移后遵循当前“常规视频只交付 MP4”的合同。

网页即时预览必须同步反映封面结尾开关和动效选择，但真实音频、逐词时间和最终动效以制作电脑本机的完整渲染为准；完整任务可从桌面窗口、Hub 网页或该电脑的本地网页发起，三者最终都调用当前电脑的本机制作服务。

## 登录与安全

- 网页不会把访问凭据放入网址或浏览器本地存储。
- 登录会话使用 HttpOnly Cookie，写操作还要经过 CSRF 校验。
- 网页与桌面账号密码固定为 8 个可见 ASCII 字符，可自由组合字母、数字和标点；服务端保存加盐并迭代计算的 verifier，不保存明文。新员工默认密码为 `xs123456`，管理员可随时重置；首次登录后建议修改，但不强制，也不作为功能或多电脑验收门槛。
- 登录按来源 IP 限速，并限制总会话数和单个 IP 会话数；这属于应用层保护，不替代 VPN、防火墙或反向代理。
- 页面只开放固定业务接口，不能通过网页调用任意桌面方法或任意主机文件。
- 文件上传按用途限制类型与大小；媒体引用与账号、会话和业务对象绑定。
- 停用成员或撤销相应凭据后，受影响的访问将失效。
- 当前局域网地址使用 HTTP，只适合可信专用局域网。不要把 8765 端口直接映射到公网；跨地点访问应先使用可信 VPN，正式公网部署应增加 HTTPS、统一身份、访问控制和审计。

## 从网页发布桌面更新

管理员可以在网页“设置 → 软件更新”上传与当前更新协议兼容的完整更新 ZIP，填写与包内一致的 SemVer 与说明并发布。Hub 会检查 ZIP 结构、内部版本、入口路径、大小与 SHA-256，再写入更新仓储；没有 `hub.manage` 权限的员工不能发布更新。实际文件名、大小和 SHA-256 以本次发布清单为准，不沿用旧版本公告值。

已安装 StoryForge 的制作电脑默认定期向 Hub 查询严格更高的核心程序版本，下载并校验后等待安全重启安装；配音或完整视频渲染进行中时会延后。Hub 主机不会自动安装自己发布的版本，应先用完整发布目录人工升级主机，再向其他制作电脑发布。

语言组件使用独立安全更新框架：清单声明组件 ID、版本、应用兼容范围和逐文件 SHA-256；客户端下载到 `<StoryForgeData>\components` 后安全解压、原子切换，并可回退上一版。组件包不能替换核心 EXE，核心程序更新也不能覆盖组件目录。`v1.0.6` 完整包可内置已验收的日语前处理、字典和约定 Voice，后续增量语种再通过组件包下发。

Hub 固定资料备份保留 72 小时且最多 3 份；相同内容按摘要去重，不重复占用空间。备份不包含员工电脑的视频素材、最终 MP4/MP3 或渲染缓存。

普通浏览器不接收桌面 ZIP。Hub 团队网页来自主机，Hub 升级后刷新即可取得新资源；制作电脑的 `127.0.0.1` 网页来自该电脑自己的发布目录，需等待该电脑更新并重启后再刷新。完整更新协议见 [AUTO_UPDATE.md](AUTO_UPDATE.md)。

## 无完整桌面窗口运行

Hub 主机和员工制作电脑分别启用自己的后台任务。

Hub 主机需要长期提供团队网页时，运行发布目录提供的 Hub 后台入口；源码目录可执行：

```powershell
& '.\scripts\enable_storyforge_hub.ps1' -DataRoot 'D:\StoryForgeHub\Data'
```

它会为当前 Windows 用户注册 `StoryForge Hub` 计划任务：登录后自动启动、同一时间只运行一个实例、异常退出后重试。

员工首次通过 EXE 使用账号密码登录后，软件自动注册 `StoryForge Local Worker` 登录任务，负责当前电脑的 TTS、素材目录、FFmpeg/GPU、队列和输出；只监听 loopback，不向局域网开放端口。正常使用无需执行任何脚本。

以下脚本仅保留给管理员在后台服务损坏时维修：

```text
admin-tools\enable_storyforge_worker.cmd
```

要人工撤销这项服务，可运行 `admin-tools\disable_storyforge_worker.cmd`。

也可只为当前会话启动无窗口网页服务：

```powershell
& '.\StoryForge Studio.exe' --web
```

源代码运行方式：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_dev.ps1 -Web -SkipInstall
```

该入口会优先使用项目中已经验证并包含 Kokoro 的 `.build-venv`，避免裸
`python` 意外落到不含本地 AI 组件的系统环境。

临时覆盖监听地址和端口：

```powershell
& '.\StoryForge Studio.exe' --web --web-host 0.0.0.0 --web-port 8765
```

`0.0.0.0` 是监听方式，不是浏览器地址。浏览器应访问 Hub 主电脑的实际局域网或 VPN 地址，例如 `http://10.0.0.225:8765/`。

## 嫁接到其他系统

网页适配层可以作为现有行为参考，但当前不是公开、稳定的 `/v1` API。嫁接时建议：

1. 保留 Catalog、LibraryService、Pipeline、Manifest 和 Artifact 合同，在外层增加版本化 Adapter/Worker API。
2. 将目标系统用户映射到 StoryForge actor 与有效权限；服务端注入所有者身份，不接受客户端自行提交。
3. 使用上传资源 ID、受控目录能力或对象存储 ID，不把任意绝对路径作为跨系统合同。
4. 保留幂等键、直接完整任务、任务所有权、失败跳过和产物清单；当前主流程不得重新加入 preview 审批门。
5. 对旧 `job_kind="preview"` 和旧批准状态只做历史数据兼容。
6. 公网部署使用 HTTPS、集中身份、速率限制、审计和独立发布者签名，不直接照搬当前局域网 HTTP 会话。

详细实体、端点和嫁接优先级见 [STORYFORGE_INTEGRATION_REPORT.md](STORYFORGE_INTEGRATION_REPORT.md)。

## 常见问题

- **页面打不开 / ERR_CONNECTION_REFUSED**：在 Hub 主电脑启动 `StoryForge Hub` 登录任务；源码目录可运行 `scripts\enable_storyforge_hub.ps1 -DataRoot <正式固定数据目录>`。确认端口为 8765，且防火墙允许专用网络访问。
- **网页能打开，但提示未连接本机制作服务**：在当前电脑重新打开完整 StoryForge，用账号密码登录一次，然后刷新 Hub 网页。软件会自动补建或修复 `StoryForge Local Worker`；仍失败时再由管理员运行诊断或维修脚本。
- **网页显示“缺少 FFmpeg”**：浏览器本身没有 FFmpeg，页面读取的是本机制作服务状态。先确认顶部已连接正确电脑；若已连接仍提示缺少，运行 `admin-tools\diagnose_storyforge.cmd`，检查完整发布目录或源码环境中的 `imageio-ffmpeg`/`STORYFORGE_FFMPEG`。
- **网页显示“Kokoro 还未配置”或日语配音失败**：先确认本机制作服务已连接并使用 `v1.0.6` 完整程序包。内置或独立语言组件位于 `<StoryForgeData>\components`，可重试或回退上一版。Hub 主机的 Kokoro 不会替员工电脑执行配音。
- **本机制作网页没有显示 / 打不开**：先完成账号密码连接并启用本机制作服务，再打开 `127.0.0.1:18765–18770` 中实际占用的地址；该地址只能在当前电脑打开。
- **本机制作网页不能选择某个目录**：把视频、音乐或输出目录设为当前电脑的默认工作目录，或先在当前电脑登记为安全根目录；软件不会沿用另一台电脑的绝对路径。
- **上传后不能保存**：确认文件类型正确，且当前账号拥有相应资料编辑权限。
- **异地访问失败**：当前版本不会自动穿透公网；使用可信 VPN 后访问 Hub 的 VPN 地址，不要直接开放 8765 端口。
